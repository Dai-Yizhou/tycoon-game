# 大富翁.io AI 人机系统技术设计文档

## 1. 项目概述

### 1.1 目标
设计并实现一个基于**遗传算法 + 擂台淘汰**的 AI 人机系统，自动进化出不同难度级别的智能玩家（简单、普通、困难），用于增强游戏的单人/多人体验。

### 1.2 核心思路
通过机器学习中的遗传算法，让 AI 在自对弈中不断进化：
1. **基因编码**：将 AI 的决策策略编码为可遗传的参数向量
2. **擂台对战**：AI 之间进行公平对战，根据战绩评估强弱
3. **分层管理**：按实力分为简单、普通、困难三个层级
4. **进化迭代**：通过交叉、变异生成子代，优秀个体进入下一代

## 2. 可行性分析

### 2.1 游戏机制适配性

| 游戏要素 | 遗传算法适配性 | 说明 |
|---------|--------------|------|
| 掷骰随机性 | ⚠️ 中等 | 掷骰结果随机，但策略决策可以优化（如资金管理、路径选择） |
| 地产购买/升级 | ✅ 高 | 决策明确，可通过参数控制购买阈值、升级时机 |
| 投资决策 | ✅ 高 | 可通过参数控制风险偏好、投资时机 |
| 天赋选择 | ✅ 高 | 可通过参数控制天赋优先级、学习策略 |
| 银行操作 | ✅ 高 | 可通过参数控制贷款/还款阈值 |
| 社交行为 | ⚠️ 中等 | 组队策略可参数化，但多人交互复杂度高 |

### 2.2 关键挑战

#### 挑战 1：随机性干扰
- **问题**：掷骰结果完全随机，单次对战结果不能准确反映 AI 实力
- **解决方案**：每场比赛重复 M 轮（建议 M=20），取平均值作为最终成绩

#### 挑战 2：基因编码维度
- **问题**：决策参数较多，需要合理的编码方案
- **解决方案**：采用实数编码 + 神经网络混合方案，基因既包含决策参数，也包含神经网络权重

#### 挑战 3：适应度评估
- **问题**：如何综合评估 AI 的实力（财产、信用值、地产数量等）
- **解决方案**：设计多维度评分体系，包含翻盘指数，加权求和得到综合适应度

#### 挑战 4：收敛速度
- **问题**：遗传算法可能收敛到局部最优，出现人类无法理解的元决策
- **解决方案**：引入随机跨层挑战（鲇鱼效应）、定期注入随机个体、增加种群多样性

#### 挑战 5：逆风翻盘能力
- **问题**：前期劣势但后期能翻盘的优质 AI 可能被提前剪枝
- **解决方案**：去除提前剪枝策略，增加翻盘指数作为加分项

### 2.3 可行性结论

**✅ 方案可行**，理由如下：
1. 游戏核心决策（购买、升级、投资、银行操作）均可参数化
2. 通过多轮对战（M=20）可以有效降低随机性影响
3. 遗传算法 + 神经网络混合方案在策略游戏中已有成功案例
4. 分层管理 + 随机跨层挑战可以确保不同难度级别的 AI 持续存在，并防止元决策
5. 增加翻盘指数和去除剪枝策略可以保留更多优质策略

```typescript
  // 地产策略（6个）
  buyThreshold: number;           // 购买资金阈值系数
  buyUrgency: number;             // 购买紧急度（0=保守，1=急切）

  gainSeeking: number;            // 收益追求度

```

**神经网络集成方案**：

```
基因结构 = 决策参数（24个） + 神经网络权重（可选）

神经网络架构：
输入层：游戏状态特征（资金、地产数量、信用值、位置、回合数等）
隐藏层：1-2 层，每层 16-32 个神经元
输出层：各决策的概率分布（购买概率、升级概率、投资概率等）

决策流程：
1. 基因参数作为基础策略
2. 神经网络根据当前状态动态调整决策概率
3. 最终决策 = 基因参数 × 神经网络输出 + 随机噪声
```

**实现建议**：
- **Phase 1**：先扩展基因参数到 24 个，不引入神经网络
- **Phase 2**：引入轻量级神经网络（1层隐藏层，16个神经元）
- **Phase 3**：根据训练效果调整神经网络复杂度

### 2.4.5 改动 5：跨层挑战随机抽取的详细评估

**可行性**：✅ 完全可行

**随机跨层挑战方案**：

```
原有方案：
- Tier 2 前几名 vs Tier 1 后几名
- Tier 3 前几名 vs Tier 2 后几名

新方案：
- 随机从 Tier 2 抽取 3-5 个 AI
- 随机从 Tier 1 抽取 3-5 个 AI
- 进行跨层对战
- 同理 Tier 3 vs Tier 2
```

**鲇鱼效应分析**：
- **防止元决策**：随机配对可以防止某个层级进化出专门针对"预期对手"的策略
- **增加不确定性**：每次跨层挑战的对手都是随机的，迫使 AI 发展通用策略
- **促进流动**：低层级的"黑马"AI 有机会直接挑战高层级，增加进化压力

**建议配置**：

| 参数 | 值 | 说明 |
|-----|-----|------|
| 跨层挑战频率 | 每 2-3 代 | 保持进化压力但不频繁 |
| 每层抽取数量 | 3-5 | 确保统计意义 |
| 对战轮数 | M=20 | 与常规对战一致 |

### 2.4.6 改动 6：减少/去除剪枝策略的详细评估

**可行性**：✅ 完全可行

**剪枝策略调整**：

| 原有策略 | 调整方案 | 理由 |
|---------|---------|------|
| 提前终止明显劣势的对战 | ❌ 去除 | 可能出现逆风翻盘的 AI |
| 跳过重复的决策路径 | ⚠️ 保留但优化 | 避免完全相同的决策，但允许相似策略 |
| 合并相似的基因个体 | ❌ 去除 | 相似不代表相同，保留多样性 |

**影响分析**：
- **优点**：
  - 保留逆风翻盘的优质 AI
  - 更多策略有机会被评估
  - 避免误判潜力股
- **缺点**：
  - 训练时间增加（没有提前终止）
  - 内存占用增加（更多对战记录）

**替代方案**：
- 不提前终止对战，但可以缩短对战回合数（如从 100 回合减少到 80 回合）
- 记录每回合的状态，用于计算翻盘指数

### 2.4.7 改动 7：增加翻盘指数的详细评估

**可行性**：✅ 完全可行

**翻盘指数计算方案**：

```
翻盘指数 = Σ(劣势程度 × 逆转幅度 × 时间权重) / 对战总回合数

其中：
- 劣势程度：某回合 AI 的排名相对于其他 AI 的差距
- 逆转幅度：从劣势到优势的变化量
- 时间权重：后期逆转权重更高（接近游戏结束时的逆转更有价值）

具体计算步骤：
1. 记录每回合每个 AI 的综合得分（财产 + 地产 + 信用值）
2. 计算每回合每个 AI 的排名
3. 识别劣势阶段（排名低于平均水平）
4. 识别逆转事件（从劣势转为优势）
5. 计算逆转的幅度和时间点
6. 加权求和得到翻盘指数
```

**翻盘指数示例**：

| 回合 | AI得分 | 排名 | 劣势标记 | 逆转事件 |
|-----|-------|------|---------|---------|
| 10 | 5000 | 4/4 | ❌ | - |
| 20 | 6000 | 4/4 | ❌ | - |
| 30 | 8000 | 3/4 | ❌ | - |
| 40 | 12000 | 2/4 | ✅ | 开始逆转 |
| 50 | 18000 | 1/4 | ✅ | 完成逆转 |
| 60 | 22000 | 1/4 | ✅ | 保持领先 |

**适应度公式更新**：

```
fitness = 0.30 × moneyScore + 0.20 × propertyScore + 0.10 × creditScore +
          0.15 × investmentScore + 0.10 × survivalScore + 0.05 × efficiencyScore +
          0.10 × comebackScore  ← 新增翻盘指数
```

**翻盘指数权重讨论**：
- 权重过高：可能导致 AI 故意"放水"制造逆转机会
- 权重过低：无法有效识别翻盘能力
- **建议权重**：0.05-0.10

### 2.4.8 改动 8：使用 20 核 CPU 的详细评估

**可行性**：✅ 完全可行

**CPU 架构分析**：

| 项目 | 规格 |
|-----|------|
| CPU | Intel Core i7-14700F |
| 物理核心 | 20 核（8P + 12E） |
| 逻辑处理器 | 28 线程 |
| P-core 频率 | 最高 5.4 GHz |
| E-core 频率 | 最高 4.2 GHz |

**大小核调度策略**：

| 策略 | 说明 | 推荐度 |
|-----|------|-------|
| 自动调度 | 让操作系统分配线程 | ⚠️ 不推荐 |
| 绑定到 P-core | 所有线程都使用性能核 | ✅ 推荐 |
| 混合绑定 | 关键线程用 P-core，辅助线程用 E-core | ⚠️ 复杂 |

**推荐方案**：

```
并行度：20（与物理核心数一致）
线程绑定：全部绑定到 P-core（8个）+ E-core（12个）
理由：
- E-core 虽然频率低，但数量多，可以处理对战模拟这类计算密集型任务
- 20 个并行对战可以充分利用所有物理核心
- 避免超线程带来的性能下降（超线程在计算密集型任务中收益有限）
```

#### 3.2.2 适应度评估（Fitness Evaluation）

**多维度评分体系（10维）**：

| 维度 | 权重 | 评分方法 |
|-----|------|---------|
| 财产得分 | 0.15 | 最终财产 / 100000（游戏胜利目标金额） |
| 地产得分 | 0.20 | (地产数量 × 平均等级 × 平均持股比例) / 15 + 地产总价值 / 60000 |
| 信用值得分 | 0.08 | 最终信用值 / 100 |
| 投资得分 | 0.12 | ROI + 0.3，上限 1.5 |
| 生存得分 | 0.15 | 生存回合数 / 总回合数（最低 0.1） |
| 效率得分 | 0.05 | 操作成功率 |
| 翻盘指数 | 0.08 | Σ(劣势程度 × 逆转幅度 × 时间权重) / 总回合数 |
| 净资产得分 | 0.12 | 净资产 / 100000（反映真实财务状况） |
| 债务健康度 | 0.03 | 1 - 总债务/净资产（债务越低得分越高） |
| 天赋得分 | 0.02 | 已学习天赋数 / 6 |

**适应度计算公式**：
```
fitness = 0.15 × moneyScore + 0.20 × propertyScore + 0.08 × creditScore +
          0.12 × investmentScore + 0.15 × survivalScore + 0.05 × efficiencyScore +
          0.08 × comebackScore + 0.12 × netWorthScore + 0.03 × debtScore +
          0.02 × talentScore
```

**地产评分公式（考虑持股比例）**：
```
propertyScore = min(
  (地产数量 × 平均等级 × 平均持股比例) / 15 + 地产总价值 / 60000 + 持股比例加成 × 0.5,
  1
)
```

**净资产评分公式**：
```
netWorthScore = min(max(净资产 / 100000, 0), 1)
```

**债务健康度评分公式**：
```
debtScore = 总债务 > 0 ? max(0, 1 - 总债务 / max(净资产, 1)) : 1
```

**天赋评分公式**：
```
talentScore = min(已学习天赋数 / 6, 1)
```

**翻盘指数计算说明**：
```
翻盘指数 = Σ(劣势程度 × 逆转幅度 × 时间权重) / 对战总回合数

其中：
- 劣势程度：某回合 AI 的排名相对于其他 AI 的差距
- 逆转幅度：从劣势转为优势的变化量
- 时间权重：后期逆转权重更高（接近游戏结束时的逆转更有价值）

计算步骤：
1. 记录每回合每个 AI 的综合得分（财产 + 地产 + 信用值）
2. 计算每回合每个 AI 的排名
3. 识别劣势阶段（排名低于平均水平）
4. 识别逆转事件（从劣势转为优势）
5. 计算逆转的幅度和时间点
6. 加权求和得到翻盘指数
```

#### 3.2.3 游戏独特机制与 AI 适配

本游戏与传统大富翁有显著差异，AI 必须针对以下独特机制进行适配：

| 机制 | 传统大富翁 | 本游戏 | AI 适配策略 |
|-----|-----------|--------|-----------|
| 地产所有权 | 独占模式（一人独占） | 股份制（多人共同持有，最多4人） | 新增 co-buy 决策，评估持股比例和所有者数量 |
| 地图结构 | 线性环形 | 图结构（多路径选择） | 路径偏好基因控制路线选择 |
| 信用系统 | 无 | 动态信用（0-100），影响贷款上限和利率 | 信用值纳入决策，贷款/还款策略考虑信用影响 |
| 贷款系统 | 固定额度 | 额度 = credit × 100，利率随信用变化 | 参数化贷款金额，基因控制贷款比例 |
| 破产规则 | 资金 < 0 | 净资产 ≤ 0 持续一段时间 | 以净资产判断，而非仅资金 |
| 天赋系统 | 无 | 数值型/开关型天赋，影响游戏机制 | 天赋类别偏好基因，经济/战略分类学习 |
| 投资事件 | 无 | 投资格子，可购买股份，有波动回报 | 投资策略基因，风险调整因子 |
| 胜利条件 | 对手破产 | 净资产达到 100000 | 适应度目标对齐胜利条件 |

**股份制地产适配**：
```
AI 决策流程：
1. 检查地产是否无所有者 → 全额购买（buy）
2. 检查地产是否有部分所有者且未达上限（≤4人）→ 参股购买（co-buy）
3. 检查是否为所有者 → 升级决策（upgrade）
4. 持股比例 = 购买价格 / (总购买价格)
5. 租金收入按持股比例分配
```

**动态信用系统适配**：
```
贷款上限 = credit × loanFactor（默认 100）
利率 = baseRate + (1 - credit/100) × creditPenalty
AI 决策：
- 高信用时：积极贷款扩张
- 低信用时：谨慎贷款，优先还款恢复信用
- 贷款金额由基因参数 loanAmountRatio 控制（0.1 ~ 1.0）
```

**破产规则适配**：
```
真实游戏规则：
- 净资产（netWorth）≤ 0 持续 5 分钟触发破产
- 破产后有 10 分钟复活期限
- 超过期限清除所有资产

AI 模拟简化：
- 每回合检查净资产
- 净资产 ≤ 0 立即判定破产（模拟时间累积效果）
- 排除复活机制（训练效率考虑）
```

**天赋策略适配**：
```
天赋分类：
- 经济类：economist, money, credit, bank, loan, income
- 战略类：investor, monopolist, explorer, property, invest

AI 决策：
- talentPriority 基因控制学习倾向（0=经济，1=战略）
- talentUnlockOrder 基因控制学习顺序
- 优先学习与当前策略匹配的天赋类别
```

**投资事件适配**：
```
投资格子特点：
- 可购买股份（与地产相同的股份制）
- 价格固定或波动
- 回报基于事件机制

AI 决策：
- investmentThreshold 控制投资门槛
- investmentHoldTime 控制持有时间偏好
- riskAdjustmentFactor 控制风险调整
- 考虑投资与地产的资产平衡
```

#### 3.2.5 遗传操作（Genetic Operations）

**修正说明**：大富翁基因是连续高维参数（30个），且参数间存在强关联（如riskTolerance和loanThreshold必须协同）。单点/均匀交叉会野蛮拆散已协同好的基因块，产生大量"畸形儿"。改用连续优化GA的黄金标准：模拟二进制交叉（SBX）+ 多项式变异。

**自适应变异率**：
```
根据种群多样性动态调整变异率：
- 多样性高时：低变异率（0.05-0.08），精细调优
- 多样性低时：高变异率（0.15-0.20），促进探索

多样性计算公式：
diversity = 1 - (平均基因相似度)
基因相似度 = Σ|g1[i] - g2[i]| / 基因维度数

自适应变异率：
mutationRate = mutationRateMin + (mutationRateMax - mutationRateMin) × (1 - diversity)
```

**交叉操作（Crossover）**：

**模拟二进制交叉（Simulated Binary Crossover, SBX）**：
```
核心思想：在连续空间中，SBX 模拟二进制交叉的特性，
产生的子代倾向于靠近父代，但有一定概率产生较远的后代。

公式：
β = (2u)^(1/(η+1))  当 u ≤ 0.5
β = (1/(2(1-u)))^(1/(η+1))  当 u > 0.5

x1' = 0.5 × [(1+β)x1 + (1-β)x2]
x2' = 0.5 × [(1-β)x1 + (1+β)x2]

其中：
- u 是 [0,1] 间的均匀随机数
- η 是分布指数（建议 η=20，值越大子代越靠近父代）

优点：
- 保留父代的协同基因块
- 产生的子代分布平滑
- 适合连续高维优化问题
```

**变异操作（Mutation）**：

**多项式变异（Polynomial Mutation）**：
```
核心思想：在基因值附近产生多项式分布的变异，
变异幅度可控，避免产生极端值。

公式：
δ = (2u)^(1/(ηm+1)) - 1  当 u ≤ 0.5
δ = 1 - (2(1-u))^(1/(ηm+1))  当 u > 0.5

x' = x + δ × (x_upper - x_lower)

其中：
- u 是 [0,1] 间的均匀随机数
- ηm 是变异分布指数（建议 ηm=20）
- x_upper, x_lower 是基因值的上下界（0 和 1）

优点：
- 变异幅度可控，避免产生"畸形儿"
- 适合连续参数的精细调优
- 与 SBX 配合使用效果最佳
```

**自适应变异率**：
- 根据种群多样性动态调整变异率
- 多样性高时：低变异率（0.05-0.08），精细调优
- 多样性低时：高变异率（0.15-0.20），促进探索

**精英保留（Elitism）**：
- 每代保留前 10-15% 的精英个体直接进入下一代
- 精英个体不参与交叉和变异

**替代方案（进化策略 ES）**：
```
如果 SBX + 多项式变异效果不佳，可改用进化策略风格：
1. 父代直接复制
2. 子代仅通过自适应高斯变异产生
3. 参考 CMA-ES 思想，协方差矩阵自适应调整

优点：
- 完全避免交叉带来的基因块拆散问题
- 变异方向自适应，效率高

缺点：
- 收敛速度可能较慢
- 需要维护协方差矩阵，实现复杂
```

#### 3.2.6 擂台对战系统（Arena System）

**对战模式**：

| 模式 | 说明 | 使用阶段 |
|-----|------|---------|
| 同层对战 | 同难度级别的 AI 之间对战 | 日常训练、排名更新 |
| 跨层对战 | 不同难度级别的 AI 之间对战 | 升级/降级判定 |
| 混战模式 | 多个 AI 同时在一个棋盘对战 | 进化筛选 |

**对战流程**：
```
1. 初始化：创建独立游戏实例，所有 AI 使用相同初始条件
2. 对战：AI 轮流行动，直到达到回合上限或只剩一个 AI
3. 记录：收集每个 AI 的各项指标（财产、地产、信用值等）
4. 评分：根据适应度函数计算每个 AI 的得分
5. 排名：根据得分对 AI 进行排名
```

**随机性控制**：
- 每场对战重复 M 轮（建议 M=20）
- 每轮使用不同的随机种子
- 最终成绩取 M 轮的平均值

#### 3.2.7 分层管理（Tier Management）

**三个层级（激进多样性配置）**：

| 层级 | 名称 | AI 数量 | 特点 |
|-----|------|--------|------|
| Tier 1 | 困难 | 50 | 最强策略，资金管理优秀 |
| Tier 2 | 普通 | 50 | 中等策略，偶尔犯错 |
| Tier 3 | 简单 | 50 | 基础策略，频繁犯错 |

**设计理由**：
- 每层50个AI，总计150个个体，极大增加种群多样性
- 更多策略组合可能被发现，进化压力更大
- 减少早熟收敛风险，更容易找到全局最优策略

**对战模式调整**：
由于每层50个AI，如果采用两两对战，每场需要 C(50,2)=1225 场，训练时间过长。因此改用**分组混战模式**：

```
分组混战规则：
1. 每层50个AI分成10组，每组5个AI
2. 每组进行一场混战（5个AI同时对战）
3. 每场混战重复 M=20 轮
4. 记录每个AI在组内的排名和得分
5. 每代进行多轮分组（如3轮），确保每个AI与不同对手对战
6. 根据多轮混战的综合成绩进行排名和淘汰
```

**分组混战优势**：
- 单代对战场次从 3675 场减少到 30-90 场（10组 × 3轮 × 3层）
- 训练时间可控
- 每个AI有机会与不同类型的对手对战
- 更接近真实游戏场景（多人混战而非双人对战）

**升降级规则（修正：基于同层基线的相对偏移 + 连胜系统）**：

**核心思想**：跨层对战的升降级不应基于绝对胜负，而应基于该 AI 在同层中的相对表现。使用"同层均分偏移"来判断，并要求连续多次满足条件才能升降级，避免偶然因素影响。

```
同层均分偏移 = 该 AI 的排名 - 同层所有 AI 的平均排名

偏移 < 0：该 AI 表现优于同层平均，有升级潜力
偏移 > 0：该 AI 表现劣于同层平均，有降级风险
```

**升级条件（从低层级到高层级）**：
```
1. 跨层对战中，同层均分偏移 < -1.0（显著优于同层平均）
2. 连续 2 次跨层挑战均满足条件

例如：T2 AI 跨层对战中排名第4，同场所有 T2 平均排名是5.5
→ 偏移 = 4 - 5.5 = -1.5（优于同层平均）
→ 应升级到 T1
```

**降级条件（从高层级到低层级）**：
```
1. 跨层对战中，同层均分偏移 > +1.0（显著劣于同层平均）
2. 连续 2 次跨层挑战均满足条件

例如：T1 AI 跨层对战中排名第6，同场所有 T1 平均排名是4.5
→ 偏移 = 6 - 4.5 = +1.5（劣于同层平均）
→ 应降级到 T2
```

**淘汰机制**：
- 仅淘汰 Tier 3 中表现最差的 20-30%（Tier 1 和 Tier 2 不淘汰）
- 淘汰后从子代中补充新个体
- 保持每个层级的 AI 数量稳定

### 4.2 详细步骤

#### 步骤 1：初始化种群
```
1. 生成 N 个随机基因个体（建议 N=80-100）
2. 每个基因参数在 [0, 1] 范围内随机生成
3. 创建对应的 AI 实例（携带基因参数）
```

#### 步骤 2：冷启动定标期（修正：替代初始分层）
```
核心思想：大富翁骰子方差极大，单次混战无法准确评估 AI 实力。
必须经过足够多代的大混战，统计稳健的适应度后再分层。

具体步骤：
1. 前 50-100 代（冷启动期），所有 AI 不分层，全部大混战
2. 每代进行多场混战（每场 4-6 个 AI，M=20 轮）
3. 记录每个 AI 的每代适应度得分
4. 计算稳健适应度：
   稳健适应度 = 平均分 - 2 × 标准差
   （减去 2 倍标准差，惩罚不稳定的"运气狗"）
5. 冷启动期结束后，按稳健适应度三等分填仓：
   - 前 1/3 → Tier 1（困难）
   - 中间 1/3 → Tier 2（普通）
   - 后 1/3 → Tier 3（简单）
6. 分层后进入正常进化流程
```

**冷启动期的作用**：
- 消除骰子随机性带来的误判
- 区分"运气狗"和"真高手"
- 为后续进化奠定正确的层级基础

#### 步骤 3：同层训练（分组混战模式）
```
1. 每层50个AI分成10组，每组5个AI
2. 每组进行一场混战（5个AI同时对战）
3. 每场混战重复 M=20 轮
4. 记录每个AI在组内的排名和得分
5. 进行3轮分组（每轮重新随机分组），确保每个AI与不同对手对战
6. 根据3轮混战的综合成绩计算每个AI的平均排名和得分
7. 每个层级内部根据综合成绩更新排名
```

#### 步骤 4：跨层挑战
```
1. Tier 2 的前几名挑战 Tier 1 的后几名
2. Tier 3 的前几名挑战 Tier 2 的后几名
3. 根据胜负结果决定升降级
```

#### 步骤 5：生成子代
```
1. 从每个层级中选择优秀个体作为父代（锦标赛选择，规模5）
2. 进行交叉操作生成子代（模拟二进制交叉 SBX，分布指数η=20）
3. 对子代进行变异操作（多项式变异，分布指数ηm=20）
4. 根据种群多样性动态调整变异率：
   - 多样性高：低变异率（0.05-0.08）
   - 多样性低：高变异率（0.15-0.20）
5. 保留精英个体直接进入下一代（前10-15%）
6. 生成新的随机个体注入种群（每代5-8个）
```

#### 步骤 6：淘汰与补充
```
1. 淘汰 Tier 3 中表现最差的 20-30%
2. 从子代中选择优秀个体补充到各层级
3. 保持每个层级的 AI 数量稳定
4. 更新各层级的排名
```

#### 步骤 7：检查终止条件
```
终止条件（满足任一即可）：
1. 达到最大迭代次数（建议 50-100 代）
2. 连续 10 代适应度没有显著提升（收敛）
3. Tier 1 的 AI 平均胜率 > 90%（相对于 Tier 3）
```

## 7. 性能优化策略

### 7.1 并行化

- **并行对战**：同时进行多场对战，利用多核 CPU
- **分布式训练**：多台机器同时训练不同层级的 AI
- **异步评估**：适应度评估与遗传操作并行执行

### 7.2 缓存机制

- 缓存地图数据和格子属性
- 缓存已计算的路径和投资回报
- 缓存 AI 的决策结果（相同状态下复用）

### 7.3 剪枝策略

> **重要说明**：根据 2.4.6 节的分析，**禁止使用提前终止逻辑**，以确保逆风翻盘的 AI 有机会完成对战，为翻盘指数（2.4.7节）提供完整数据。

- ❌ **禁用**：提前终止明显劣势的对战（会误杀翻盘 AI）
- ⚠️ **保留**：跳过重复的决策路径（避免完全相同的决策，但允许相似策略）
- ❌ **禁用**：合并相似的基因个体（相似不代表相同，保留多样性）

| 单场对战（M=20） | ~1000 MB | 20 轮对战的状态快照 |
| 种群数据 | ~15 MB | 150 个基因个体，每个约 100 字节 |
| 对战结果缓存 | ~200 MB | 存储近期对战历史（含翻盘指数计算数据） |
| **总计** | **~1.2 GB** | 单线程训练 |
| **并行20线程** | **~8-10 GB** | 20 场对战同时进行（推荐配置） |
| **并行28线程** | **~11.5-14 GB** | 28 场对战同时进行 |

> **注意**：本机可用内存约 14.98 GB，支持并行 20 线程训练，建议预留部分内存给系统和其他应用。

#### 8.4.2 CPU 占用

| 模式 | CPU 占用 | 说明 |
|-----|---------|------|
| 单线程训练 | ~4% | 仅使用一个核心 |
| 并行训练 | ~80-90% | 充分利用多核 CPU |

### 8.5 训练策略建议

#### 8.5.1 推荐配置

基于本机硬件（i7-14700F，20核，32GB内存），推荐以下训练配置：

| 参数 | 推荐值 | 理由 |
|-----|-------|------|
| `populationSize` | 150 | 激进多样性配置，每层50个AI |
| `maxGenerations` | 120 | 含60代冷启动期 |
| `roundsPerMatch` | 20 | 大幅降低随机性影响 |
| `parallelMatches` | 20 | 充分利用CPU，内存占用约8-10 GB |
| `elitismRatio` | 0.12 | 保留精英个体 |
| `groupSize` | 5 | 分组混战每组AI数量 |
| `groupRoundsPerGeneration` | 3 | 每代分组混战轮数 |

## 10. 部署与使用

### 10.1 训练流程

```bash
# 安装依赖
pnpm install

# 启动训练（默认配置）
pnpm run train

# 启动训练（自定义配置）
pnpm run train --config config/evolution.config.ts

# 查看训练进度
pnpm run train --verbose

# 导出训练好的 AI
pnpm run export --output ./trained-ai/
```

### 10.2 集成到游戏

训练完成后，将各层级的最优基因导出为 JSON 配置：

```json
{
  "easy": {
    "genes": [/* Tier 3 最优基因 */],
    "name": "简单"
  },
  "normal": {
    "genes": [/* Tier 2 最优基因 */],
    "name": "普通"
  },
  "hard": {
    "genes": [/* Tier 1 最优基因 */],
    "name": "困难"
  }
}
```

游戏客户端根据玩家选择的难度，加载对应级别的 AI 基因配置。

## 11. 风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|-----|------|------|---------|
| 过拟合 | 中 | AI 只适应特定地图 | 多地图轮换训练 |
| 早熟收敛 | 中 | 种群多样性丧失 | 定期注入随机个体 |
| 计算资源消耗 | 高 | 训练时间过长 | 并行化、剪枝 |
| 随机性干扰 | 高 | 评估不准确 | 多轮对战取平均 |
| 参数敏感性 | 中 | 配置不当影响结果 | 参数调优、网格搜索 |
