# 前端质感优化方向 — 范围与关键决策清单

> 本文沉淀一次关于**前端 UI 质感提升**的讨论。**问题范围以线上分享记录为准**（`share.traecontent.cn/Z5A8P3Z6PBBKJO`，13 条质感优化方向及其评审），本文在其基础上补充：架构事实核对、几处关键设计决策（尤其"区域令牌过渡"）与技术选型。供内测前架构决策阶段使用。

---

## 0. 结论速览

1. 全局 UI 主题的"整套换皮"模型已**推翻**。
2. **区域视觉＝地图内容**：每区域声明自己的地图视觉（表面色/格子填充/边框/线型/纹理/字体），随地图走，与全局 UI 主题**分离**。
3. **区域变换＝静态地图 + HUD 自适应**：整幅地图一次 build（所有区域同屏、过渡烧入静态图），相机 viewBox 平移，无"换皮事件"；**全局 UI 主题废除**，HUD 收敛为单一中立悬浮面板 + 对比自算。
4. **过渡由人工掌控**：不做程序化颜色插值——样式含字体/线条/边框等离散决策，作者在所见即所得编辑器里手绘/指定过渡带。
5. **昼夜**＝在静态图与区域视觉之上叠加"夜晚光照层"，用 `localProgress` 连续插值（客户端时间即可，不严格校验）。
6. **纪律**：不引外部资产/音频/图片、无粒子（吃性能）、克制、`prefers-reduced-motion` 可整体关。

## 1. 范围基线（来自在线记录，13 条质感优化方向）

1. 内测不上重资产管理，不引入音频、图片；尽量找到美术/音效，开发工作流前必须先做架构决策、对齐思路与设计取向。
2. 格子＝地块+文字 → 减弱文字，加类型图标（8 个），填充样式。
3. 棋子单一 → 按图稿差分、拼入 SVG 图像解析（轻资产）、按角色语义/积分分配。
4. 连线 → 加方向指示、弱化。
5. 背景层次感 → 背景多层纹理，格子/连线阴影分层（浮动感，克制），不要粒子。
6. 棋子滑行移动 → 加段落感（观察真实下棋移子），减速。
7. 技能节点清晰 → 顶中放 rentfree 相关 + 补网页图标。
8. 拼图块点数提示 → 复用按钮簇显示数字，"已移动/总步数"，完成后关闭。
9. 数值图形化 → 滚动+底色呼吸提示变化，避免一直滚（保持数值清晰、不造成视觉干扰）。
10. 操作不止点按 → 保留按钮，附加新交互（桌面/移动端适配）：带提示的快照键、鼠标动作/触控手势。
11. 昼夜并呈现 → 启用 night 令牌 + 页面光照呼吸（+ 按光照角算阴影）。
12. 控件过小 → 桌面端适当放大、移动端可读性。
13. 入口时序：先架构决策与设计取向对齐，后内测开跑。

> 本文不逐条复述，重点记录会影响实现的**关键决策**（见 §3–§6）。13 条多数落在"框架层"（固定、不依赖地图、不引资产）；少数（棋子角色、区域纹理、昼夜光照）牵涉"地图声明/库属绑定"，需架构对齐后做。

## 3. 关键决策一：区域变换＝静态地图 + HUD 自适应（替代"整套换皮"与全局 UI 主题）

### 3.1 概念模型

- 相机＝viewBox 平移（现状 `applyViewBox`）；地图＝**一张整幅静态矢量画布**，所有区域同屏一次 build。
- "移动"＝摄像机移动，玩家始终只见地图一小部分 → **区域过渡直接烧进静态图，不存在"换皮事件"**。
- **区域视觉从全局 UI 主题中剥离**：区域定义自己的地图视觉，作为**地图内容**随地图走，不再是全局主题。

### 3.2 随后的架构收敛：废除"全局 UI 主题"

- 现状 4 套区域主题（northeast/south/midwest/west）把**地图视觉**与 **HUD 框架**混在一个 token 集里（见 §2），换区域＝整套换皮。
- 既然地图视觉改由每区域声明并静态烧入，**全局 `--gp-*` 根注入的主题对地图不再有意义** → 取消/重构：
  - `content`(区域)部分 → 下沉为地图内容里的区域视觉规格；格子就地取所属区域色。
  - `framework`(HUD)部分 → 收敛为"单一中立悬浮面板 + 对比自算"，不随区域变。
  - `cell.theme`、`RegionThemeConfig.themeId` 字段可废弃或重定义。
- 注：决策 §5 与 §4 的"在中立 HUD 上自算对比度、在静态图/区域视觉上叠加昼夜光照"与本收敛一致。

### 3.3 过渡：人工掌控，不做程序化插值（推翻"自动混合缓冲带"）

- **颜色不总该插值过渡**；且样式含字体/线条/边框/纹理等**离散决策**，无法用颜色 mix 表达。
- 每个区域相邻边给**显式、人工编写的过渡声明**（作者绘制/指定渐变带），而非运行时按基色自动混合。
- 离散项（字重/边框/线型突变）沿网格边界自然切换；连续项（底色）才用作者指定的渐变带。

### 3.4 如何产出（专业化方案：所见即所得 + 共享渲染管线）

- 目标：**最终的合成图像对人类编辑者可见、可控**。
- **地图视觉＝地图内容数据**：每区域声明其视觉规格（区域级 token），与格子/文本同源、同在编辑器里编辑、随地图版本化。
- **所见即所得编辑器**：直接渲染"完整静态地图"（全区域+连线+文字+过渡），编辑者肉眼改/审（表面色、格子填充、边框、线型、纹理、字体、手画过渡带）。
- **共享渲染管线**：编辑器预览与客户端运行时调用**同一渲染代码** → 编辑器所见＝玩家所见；可 headless 导出单张合成 SVG / PNG 预览，作为可审查、可版本化产物。
- 客户端只做：加载这份"视觉已合成"的静态图 + 相机平移 + 叠加层（棋子/所有权/数值/昼夜光照）。

## 4. 关键决策二：昼夜＝"整套基色 + 夜晚光照叠加层"

- 不做"两套完整主题"（白天/夜晚各一套完整值表）：有突变点、维护×2。
- 做**主题基色一套 + 可调夜晚叠加层**（暗化 tint + 冷调 + 微光晕），连续系数控强度。
- 系数＝`localProgress` 平滑函数（白天≈0 → 黄昏过渡带 → 夜晚≈1），客户端 RAF 逐帧对叠加层 `opacity`/blend 插值。
- **用客户端时间即可，不严格校验**：`cycleMinutes`/起始/`serverTimeOffset` 已由服务端下发。
- 与区域换皮**正交可叠加**：区域定"整套基色"，昼夜在基色上做光照。

## 5. 其他已对齐的决定（供实施参照）

| 项 | 选型 | 备注 |
|---|---|---|
| 阴影 | CSS `drop-shadow` + `transition`；"格子躺桌面/棋子浮起"两档、统一光源、暖调、克制 | 零资产、GPU 合成；数值做令牌 |
| 加成交互 | Pointer Events（通吃鼠标/触屏/笔）+ 现有 cellChoice + CSS transform 过渡 + 快捷键提示兜底 | 零新增库；不引 GSAP |
| 可选目标格 | 拖/点到 cellChoice 集内 → `onPathChoice`；按钮簇保留兜底 | 桌面+移动一套逻辑 |
| 棋子移动 | 段落感+落地手感（接现有 hooks）；注意与服务端快照纠正协调，防减速被"跳"打断 | |
| 数值反馈 | 滚动+底色呼吸，避免一直滚 | 仅本地结算瞬时滚动，非全量广播 |
| 性能 | 砍"逐对象方向阴影"，只做全局光照呼吸 | 与"不吃粒子"一致 |
| 克制度量 | 不引资产、无粒子、`prefers-reduced-motion` 线性关 | CSS 媒体查询+令牌开关 |

### 8.4 判断依据

- 内测价值 = 上线可玩 + 页面不"廉价"。两者最小充分集 = §8.1 + §8.2 的 P2。

## 9. 内测前已定实施项：定义与边界

> 本节只做**定义与边界细化**，不含代码改动。

### 9.1 连线方向指示（内测前实施）

- **语义来源**（单向/双向判定来自地图数据 `destinations`）：
  - 单向边：`A.destinations` 含 B，但 `B.destinations` 不含 A → 方向 A→B。
  - 双向边：A、B 互相含于对方的 `destinations` → 无方向箭头。
  - `destinations` 为空/缺失：不画线（现状不变）。
- **渲染**：无向去重线形态不变（按无序对去重，一条线）；**单向边在其目标端加方向箭头**，双向边保持裸线（无箭头）。用**单个 SVG `<marker>`**（`refX` 对准箭头端沿线角度）复用，`marker-end` 仅挂到单向线上。
- **弱化纪律**：箭头小、低调、与 `map-link` 同色系、低对比，不喧宾；不引 asset。
- **边界**：只解决"单/双向歧义"；不新增多路径弯路、不强化连线（"弱化"基线不变）；折叠自环/重复对的行为不变。
- **落地位置**：`InteractiveMapSurface.ts` 的 links 构建段（现按无序对去重），在此补 `isBidirectional(a,b)` 判定 + marker 挂载。

### 9.2 主题折中：调近 4 主题 + 移除黑屏转场（内测前实施）

- **目标**：不实施 §3 重构的前提下，消除"区域切换＝整套换皮"的割裂感。
- **调近 4 主题**：保留 region 各自主题，但把 4 套（northeast/south/midwest/west）中**可感差异显著的令牌**收敛到"观感近似"——主要调 `board / cell fill / fg / line / 边框`，保留含蓄区分但不突兀。改动落在主题 JSON（改令牌值，不动架构与消费面 `--gp-*`）。
- **移除黑屏转场**：`applyRegionTheme` 中 `gameEffects.onThemeChange`（covering→apply→revealing 的盖屏遮罩）**不再触发**；主题变化时**直接 `applyGamePageThemeTokens`**。首次与非首次一律直接应用。
- **边界/回退**：
  - 保留 `appliedRegionThemeId` 去重（避免每次位置同步重刷令牌）。
  - 保留 `localStorage(SAVED_REGION_THEME_KEY)` 沿用机制（供欢迎/登录页调性一致）。
  - 移除的只是**盖屏转场**，不是主题解析/注入逻辑本身。
- **衔接**：该折中属 §3 重构前的**临时过渡**；重构落地后取消并按 §3 重来。

### 9.3 棋子差分：按角色剪影（异会话实施，本会话不写码）

- **决策**：采用**不同角色剪影**，按**角色语义分配**——本人 / 队友 / 其他人 三类，分别映射现有 `--gp-player-self / --gp-player-teammate / --gp-player-other` 的角色语义，**保证样式稳定**（对局中不随积分动态跳变）。
- **弃用**"按积分分配"（积分动态变化会导致整局中途形象跳变，出戏）。
- **实施**：在**另一会话**落地；本条目仅记录决策与边界。
- **参考草稿**：`docs/legacy/ui/pages/piece-motion-variants.html`（几何母版 / 描边 / 状态 / 配色）作基础；角色剪影在其上新增。
- **边界**：沿用母版规格（30×56、3px 墨描边、inset 3px 内填、`transform-origin: bottom center`、禁止 fill 覆盖描边）与状态/动作变式；剪影替换只作用于"不同角色形态"。
