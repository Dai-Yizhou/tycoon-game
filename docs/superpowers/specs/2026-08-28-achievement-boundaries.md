# 成就系统需求边界

## 1. 目标

在现有单一 `GameWorld`、账号认证、UCT、运行时状态、实时榜单和领域事件基础上，增加账号级成就记录与展示能力。第一期成就只用于展示，不提供 UCT、称号、外观或其他游戏奖励。

## 2. 已确认决策

- 成就使用稳定且全局唯一的 `id` 标识。
- 成就定义显式声明 `scope`：`map` 或 `global`。
- `map` 成就按账号与 `mapId` 分别保存进度。
- `global` 成就跨地图累计或读取全局状态。
- 成就永久一次性解锁，不撤销、不重置、不重复解锁。
- 未解锁成就默认可展示；是否展示数值进度由每个成就配置决定。
- 解锁进度和完成判定由服务端负责，客户端不自行计算。
- 首次解锁实时推送一次通知。
- 成就面板只展示当前账号自己的成就。
- 配置加载或配置校验失败时，服务端启动失败。
- 成就定义存放于独立成就配置，不嵌入 `map-meta`。
- 第一阶段采用混合触发模型：通用规则配置化，复杂规则使用服务端注册规则。
- 规则输入仅限可信服务端领域事件、玩家/世界快照和历史统计；不接受客户端提交的计数、时间或完成结果。
- 暂不设计成就定义版本迁移；配置变更由后续专项处理。

## 3. 账号、游客与持久化边界

正式账号的解锁记录和累计进度绑定账号身份，跨设备、重连和世界恢复保留。

游客成就记录绑定游客 token 对应的 `playerId`，重连时恢复。游客升级为正式账号时执行完整合并：

- 同一成就任一侧已解锁，则合并结果为已解锁。
- 未解锁成就的累计进度取合并前两侧的较高值。
- 已解锁成就的解锁时间只保留一次，合并操作不得重复产生解锁通知。
- 合并必须幂等，重复执行不得增加进度或生成重复记录。

成就持久化不改变 `WorldStore` 作为玩家位置、UCT、队伍、产权和区域运行时状态唯一事实源的约束。成就数据属于账号域，不应写入静态地图、`Cell.extra` 或客户端本地作为权威数据。

## 4. 成就定义模型

概念模型如下，具体字段名称由实现计划阶段按现有 TypeScript 约定确定：

```ts
interface AchievementDefinition {
  id: string;
  scope: 'map' | 'global';
  name: LocalizedText;
  description: LocalizedText;
  category: 'movement' | 'economy' | 'social' | 'event' | 'ranking';
  progress?: {
    visible: boolean;
    target: number;
  };
  trigger: AchievementTrigger;
}
```

配置要求：

- `id` 必须非空且在配置集合中唯一。
- 本地化名称和描述必须满足现有双语配置约定。
- `scope`、`category`、触发类型及其参数必须严格校验。
- 引用的 `cellId`、`eventId`、UCT 字段和榜单字段必须符合对应领域契约。
- 数值阈值必须是有限数值；数量和排名必须是正整数。
- 同一配置不能声明互相矛盾的范围和触发参数。
- 不允许脚本、任意表达式或客户端可注入规则。

## 5. 通用触发类型边界

### 5.1 访问格子集合

用于“踩中过当前地图的每一个格子”。

- 仅适用于 `map` scope。
- 配置 `cellIds: number[]`，允许一个或多个目标格子。
- 服务端在确认玩家到达格子后按 `cellId` 去重记录。
- 重复到达同一格不增加进度。
- 目标集合全部命中后永久解锁。
- 进度为已命中目标格子数 / 目标格子总数。

### 5.2 指定事件

用于“触发事件格的一个指定事件”。

- 默认适用于 `map` scope；若后续允许全局事件，必须由配置显式声明。
- 配置 `cellIds: number[]` 与 `eventIds: string[]`，均允许数组。
- 采用组合满足：事件来源格子的 `cellId` 必须命中 `cellIds`，服务端确认的 `eventId` 必须命中 `eventIds`。
- 事件必须已经完成服务端权威结算；客户端发送的事件名称或结果不参与解锁。
- 同一成就可将满足过的合法组合按事件标识去重记录。

### 5.3 UCT 阈值

用于“现金超过指定值”等成就。

- 配置 `fieldId` 和 `target`。
- `fieldId` 必须引用已定义的 `player` scope UCT 字段。
- 第一阶段比较符固定为 `gte`，完成条件为 `current >= target`。
- 服务端读取玩家当前 UCT 值进行判定。
- 达成后即使该字段之后下降也不撤销。
- 进度展示由成就配置决定；客户端只展示服务端返回的进度。

### 5.4 当前持有投资格数量

用于“在当前地图持有 n 个股份”。

- 仅适用于 `map` scope。
- 统计当前地图上玩家 `share > 0` 的不同 `cellId` 数量。
- 地产和投资项目均属于可统计的合租/持有格类型。
- 每个格子最多计数一次，不按 share 数量累加。
- 同一格存在多个 ownership 时，当前玩家仍只计一格。
- 失去格子后，未解锁成就的当前进度允许下降；已解锁状态不撤销。

### 5.5 历史购买投资格数量

用于“首次游玩以来累计购买过 n 个股份”。

- 适用于 `global` scope。
- 统计账号历史上服务端确认成功购买过的不同 `cellId` 数量。
- 地产和投资项目均纳入。
- 同一格重复购买不重复计数。
- 出售不减少历史进度。
- 跨地图累计。
- 只有成功完成的服务端购买事件才能推进该指标。

### 5.6 榜单排名达到阈值

用于“登顶实时榜单”及其泛化形式。

- 适用于 `global` scope。
- 配置 `targetRank`，必须为正整数；`targetRank: 1` 表示登顶。
- 服务端实时榜单正式结算后，玩家排名 `<= targetRank` 时永久解锁。
- 榜单关闭、未启用或没有正式排名时不推进。
- 成就系统复用榜单服务端生成的排名，不自行计算榜单积分。

## 6. 复杂规则注册边界

复杂成就允许服务端注册命名规则，但规则必须满足以下限制：

- 规则名称必须由服务端代码静态注册，配置只能引用已注册名称。
- 规则输入只能来自结构化可信领域事件、当前玩家/世界快照和持久化历史统计。
- 规则不得执行配置脚本、任意代码或未限制的表达式。
- 规则输出必须是标准化进度结果：当前进度、目标值、是否完成以及必要的去重键。
- 规则必须支持重复事件幂等处理。
- 规则不得直接绕过成就仓储修改其他账号的解锁状态。
- 规则异常不得产生部分解锁；应记录服务端错误并保持此前一致状态。

## 7. 服务端职责

服务端负责：

- 加载并严格校验独立成就配置。
- 订阅并处理可信领域事件。
- 读取玩家、队伍、世界运行时状态和历史统计。
- 计算并持久化账号级或地图级进度。
- 保证解锁一次性、幂等和游客迁移安全。
- 向当前玩家返回成就列表快照。
- 首次解锁时推送一次成就解锁事件和通知数据。
- 在登录、重连和游客升级后返回合并后的权威状态。

## 8. 客户端职责

客户端负责：

- 保存服务端成就快照。
- 提供 HUD 成就入口和成就面板。
- 展示全部可见成就、解锁状态、服务端进度和描述。
- 展示实时解锁通知。
- 区分加载、空数据、离线、错误和未启用状态。
- 不读取 UCT、地图遍历结果、ownership 或榜单数据来本地推导成就。
- 不提交进度、计数、完成结果或解锁请求。

## 9. 非功能要求

- 服务端是唯一权威判定方。
- 进度更新和解锁记录需要具备幂等性。
- 成就状态更新不得破坏现有玩家运行时状态事务。
- 重要领域事件必须先完成其业务结算，再推进成就。
- 成就系统故障不得静默伪造解锁；错误必须可观测。
- 不在客户端日志、网络 payload 或服务端日志中输出敏感认证信息。

## 10. 非目标

第一期不包含：

- UCT、称号、外观或道具奖励。
- 成就撤销、重置或重复完成。
- 查看其他玩家成就。
- 管理员成就管理接口。
- 在线编辑或热更新成就配置。
- 成就定义版本迁移。
- 客户端自定义成就。
- 独立事件日志平台。
- 基于不可信客户端数据的成就推进。

## 11. 非承诺示例清单

以下示例用于验证模型，不锁定正式 ID、文案和目标值：

1. 访问当前地图指定的全部目标格子：`map` scope，目标格子数组，按 `cellId` 去重。
2. 在指定事件格触发指定事件：`map` scope，`cellIds[]` 与 `eventIds[]` 采用组合满足。
3. 某个玩家 UCT 字段达到阈值：`map` scope，字段由配置指定，使用 `current >= target`。
4. 当前地图持有指定数量的地产/投资项目格：`map` scope，按持有 `cellId` 去重。
5. 首次游玩以来购买过指定数量的地产/投资项目格：`global` scope，按历史成功购买的 `cellId` 去重。
6. 达到实时榜单前 N 名：`global` scope，按服务端正式排名与配置的 `targetRank` 判定。

## 12. 验收边界

需求边界完成后，实施阶段至少应覆盖：

- 配置加载、唯一 ID 和非法引用校验。
- 地图级与全局级进度隔离。
- 六类示例触发语义。
- 事件组合匹配和重复事件幂等。
- UCT 阈值达到与达成后下降。
- 当前持有格去重与出售后的未解锁进度下降。
- 历史购买格去重与跨地图累计。
- 榜单排名阈值与榜单关闭边界。
- 正式账号持久化、游客重连和游客升级合并。
- 重复解锁不重复通知。
- 客户端只展示服务端状态，不本地计算进度。
- 加载、离线、错误、空数据和解锁通知状态。
