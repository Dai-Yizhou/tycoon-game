# Beta 制作边界剩余修复项

## 1. 文档目的

本文件根据 Issue #3、`visual-effects-production-boundary.md`、`achievement-boundaries.md` 以及当前 `dev-Dai` 工作区重新核对上一版 Beta 全量审查，排除不属于工程修复范围的内容，记录后续可执行修复项。

本文件只记录工程实现、调用链、生命周期、测试和验收缺口，不承担地图内容设计或成就内容创意。

## 2. 已确认范围

### 2.1 不在本轮修复

- 地图格子数量、路线、区域、事件格、投资格和地图趣味内容。
- 地图配置文件的内容编写。
- 成就清单、成就名称、文案、目标值、目标格和目标事件的设计。
- 成就配置内容创意。
- i18n 精翻。
- 道具、天赋、复杂地图机制。
- 复杂粒子、纹理、音频、全屏转场和重型视效运行时。
- `/report` 管理端导出接口。

Issue #3 评论提出的地图 20–30 格和 4–6 个成就属于内容/配置交付，不作为本文件的工程修复项。

### 2.2 已确认实现事实

- 成就已具备 Mongo 和文件存储实现，上一版“成就仅为内存存储”的结论已过时，不再作为当前阻断项。
- 游客转正不改变用户 ID；成就与稳定 ID 绑定，不应执行游客成就迁移或合并。
- `/report` 按当前决策只要求清洗、限长、限频并落结构化日志，不新增导出系统。
- 成就面板已经增加 `achievements` 订阅和局部刷新，上一版“已打开面板不会刷新”的结论已被当前改动修正，但仍需回归测试确认。
- 当前基础移动动画已接入真实页面 RAF，视效开关、SVG 不重建和移动生命周期 hook 已存在。

## 3. 上一版审查需要纠正的结论

| 上一版结论 | 当前核对结果 | 处理方式 |
|---|---|---|
| 成就使用 `InMemoryAchievementStore`，重启后丢失 | 当前 `app.ts` 按 `MONGO_URI` 使用 `MongoAchievementStore`，无 Mongo 时使用 `FileAchievementStore` | 从当前阻断项移除；改为验证存储关闭、重启恢复和并发一致性 |
| 游客成就需要迁移/合并 | 已确认游客转正不改 ID，成就和玩家绑定稳定 ID | 从修复项移除；应删除成就迁移调用和合并路径 |
| `/report` 需要新增导出接口 | 已确认按 Issue 评论最低交付只需落结构化日志 | 从修复项移除；只验证 `/report` 日志链路 |
| 成就面板不会实时刷新 | 当前 `GameHudShell` 已订阅 `achievements` 并调用 `updateAchievements()` | 从确定性问题改为回归验证项 |
| 地图 8 格是工程阻断 | 地图内容和配置属于内容创意，不在本轮工程修复 | 保留为 Beta 总体外部依赖，不列入本修复批次 |

## 4. 剩余修复项

### P0-1：移除成就游客迁移/合并路径

当前仍存在：

- `AchievementStore.merge()`；
- `AchievementManager.mergeOwners()`；
- `AuthService.setAchievementMigration()`；
- `app.ts` 注册迁移回调；
- `AuthService.migrateGuest()` 调用成就迁移。

这与已确认的稳定 ID 规则冲突。游客转正只改变账号属性，不改变用户 ID，成就记录应继续使用原有 owner ID。

验收要求：

- 游客转正前后用户 ID 不变；
- 转正前创建的成就记录可以用转正后的 owner 读取；
- 转正过程不调用成就 merge；
- 不产生重复解锁通知；
- 不保留无业务调用者的迁移接口和合并路径。

建议拆分为一个独立小修复，不改账号数据模型。

### P0-2：补齐六类成就的真实服务端触发闭环

不修改成就配置，只补已有业务事件到成就管理器的调用链：

| 触发类型 | 当前状态 | 需要确认或修复 |
|---|---|---|
| `visitCells` | 移动和落点已有调用 | 验证移动路径去重、重复事件幂等和真实对局调用 |
| `completeEvents` | `EventHandler` 已有事件回调 | 验证事件完成后才推进，并统一组合键语义 |
| `uctThreshold` | manager 方法存在 | 接入可信 UCT 更新完成后的统一入口 |
| `ownedCells` | manager 方法存在 | 接入 ownership 变化、破产清算等已有状态变化入口 |
| `purchasedCells` | 地产和投资购买成功后已有回调 | 验证只在成功结算后推进，重复购买不重复计数 |
| `ranking` | manager 方法存在 | 接入榜单正式刷新后的服务端排名结果 |

验收要求：

- 客户端不能提交进度、计数或完成结果；
- 所有推进发生在服务端权威结算之后；
- 已解锁成就不撤销；
- 未解锁的 `ownedCells` 进度可以下降；
- 重复领域事件不重复通知；
- 六类触发各有至少一条真实业务链路测试。

### P0-3：为成就更新增加 owner 级并发保护

当前 `AchievementManager.update()` 采用加载、修改、保存流程，多个异步事件可能同时读取同一旧记录并互相覆盖，也可能同时生成重复解锁通知。

重点场景：

- 同时到达的移动路径事件；
- 购买事件和 UCT 更新同时到达；
- 榜单刷新与其他领域事件并发；
- 同一玩家多 Socket 重复投递。

验收要求：

- 同一 owner 的更新按顺序执行；
- `seenKeys` 不丢失；
- 已解锁状态不会被旧写入覆盖；
- 同一成就只发送一次首次解锁通知；
- 不改变现有 Socket 协议。

### P1-1：统一 `completeEvents` 的累计和去重语义

当前 manager 使用 `${cellId}:${eventId}` 作为去重键，规则注册表也存在一份独立实现。需要统一实际运行路径，避免 manager 和规则注册表表达不同业务语义。

验收要求：

- 合法来源格子和合法事件 ID 才能推进；
- 相同 `(cellId,eventId)` 重复触发不增加进度；
- 多个合法组合可累计；
- 规则的 `current`、`target` 与实际配置语义一致；
- 事件必须在权威结算完成后推进。

### P1-2：补齐 `ownedCells` 的状态变化入口

`recordOwnedCells()` 已支持按不同 `cellId` 去重并覆盖当前进度，但当前需要确认所有已有 ownership 变化都能触发重算。

覆盖范围：

- 地产购买；
- 投资购买；
- 已有股份变化；
- 破产清算；
- 其他现有 ownership 删除或替换路径。

不新增出售玩法，不新增 ownership 规则，只消费已有权威状态。

### P1-3：补齐榜单成就的正式刷新入口

`recordRanking()` 已存在，但需要接入 `LeaderboardManager.flush()` 的正式结果。

验收要求：

- 只使用服务端正式排名；
- 榜单关闭、未启用或无正式排名时不推进；
- `rank <= targetRank` 时一次性解锁；
- 排名下降后不撤销；
- 成就系统不重新计算榜单积分。

### P1-4：补齐 UCT 成就的统一更新入口

`recordUct()` 已存在，但需要接入已有玩家 UCT 权威更新完成的位置，避免只在个别 handler 调用或完全不调用。

验收要求：

- 使用服务端更新后的玩家快照；
- 比较符固定为 `current >= target`；
- 达成后字段下降不撤销；
- 不读取客户端提交的数值。

### P1-5：核对成就存储的生命周期和重启恢复

当前已经有 `MongoAchievementStore` 和 `FileAchievementStore`，但 `achievementStore` 尚未明显纳入 `CreatedApp` 返回值和 `gracefulShutdown()` 参数链。

需要确认：

- Mongo client 在正常停服时关闭；
- bootstrap 失败时关闭已创建的成就存储连接；
- 最后一次写入不会因停服被遗弃；
- Mongo 重启后成就记录、进度、去重键和解锁时间可恢复；
- 文件模式仍能正常工作。

### P1-6：验证成就面板打开期间的实时刷新

当前代码已经加入：

- `GameViewModel` 的 `achievements` 状态变更通知；
- `GameHudShell` 对 `achievements` 的订阅；
- 面板存在时调用 `updateAchievements()`。

需要补充回归验证：

- 面板打开时收到 `server.achievementUnlocked` 会更新内容；
- 不重复追加面板节点；
- loading、empty、offline、error、disabled 状态可理解；
- 解锁通知和面板状态最终一致。

### P1-7：补齐基础移动动画的异常状态验收

不新增复杂视效，只验证现有基础移动链路：

- 传送不会被误当作普通逐格动画；
- 动画期间收到权威快照可以停止、追赶或重置；
- 断线重连不会停在半格；
- 页面销毁后 RAF、timer 和监听器不残留；
- reduced-motion 下动态明显减少或停止；
- 视效关闭后核心玩法仍可正常完成。

这部分属于现有视效边界内的修复和验证，不增加粒子、纹理、音频或复杂转场。

### P2-1：保持 `/report` 现有最低交付并补验证

本轮不增加导出接口、不增加管理后台，只验证：

- `/report` 可通过正常聊天入口提交；
- 内容清洗、禁止词过滤、限长、限频有效；
- 日志包含反馈 ID、玩家 ID、世界 ID、格子 ID 和时间；
- 不输出认证 token、密码或其他敏感信息；
- 失败时客户端收到可理解反馈。

### P2-2：消除未接入的平行成就规则实现

当前存在 `achievementRules`，但主要业务逻辑仍在 `AchievementManager` 内部。应选择一个统一入口：

- 让 manager 统一调用静态注册规则；或
- 删除没有生产调用者的规则注册表。

不新增规则类型，不改变成就配置模型。

### P2-3：修正 shared 性能测试稳定性

`MapIndex` 的构造性能测试曾出现 `<5ms` 阈值被环境抖动击穿。该问题与成就和地图内容无关，但会影响 Beta 验收可信度。

建议作为独立测试维护项处理：

- 保持性能意图；
- 避免过窄的单次绝对阈值；
- 与功能测试结果分开解释。

## 8. 当前判定

在不考虑地图内容和成就配置创意的前提下，当前剩余阻断主要集中在：

1. 成就迁移/合并路径与稳定 ID 决策冲突；
2. 六类成就触发入口和并发一致性仍需闭环；
3. 成就存储生命周期和真实重启恢复证据不足；
4. 基础移动动画的异常状态和人工验收仍未完成；
5. 多人真实流程尚未形成可重复的 Beta smoke 证据。

本文件不判定地图是否“够玩”，也不判定成就清单是否有创意；这些属于内容创意和配置验收。
