# AI 指南：如何正确使用设计系统

> 本文档面向 AI 编程助手，说明如何在与设计系统交互时**不产出奇怪的东西**。

---

## 一、修改设计样式时

1. 先在现有色板中找接近的颜色，不要引入全新色系
2. 新增组件样式时，复制一个已有组件的定义，只改颜色引用
3. 新增主题时，复制默认主题结构，只覆盖需要不同的字段
4. 不确定风格方向时，先问人类要参考截图或 URL

## 二、判断数据归属时

纯值（颜色、尺寸、路径、动画参数、粒子参数）→ 放 JSON 文件。

逻辑（条件判断、循环、插值、物理模拟、布局计算、内容自适应策略）→ 放渲染层代码。

## 三、修改设计文件时

1. 先读完整文件结构，理解色板→语义→组件的三层引用链
2. 找到要改的 token 路径，确认修改不会破坏引用链
3. 修改后检查：JSON 语法正确？引用的色值存在？没有在 JSON 中写逻辑？
4. 新增 token 时，优先复用现有色板中的值，而不是凭空造新色值

## 四、修改渲染层时

所有颜色值、字体大小、间距、阴影、圆角、动画参数、粒子参数都必须从 adapter 接口查询，不得在渲染层代码中写死任何样式值。

## 五、人类提供参考图时

1. 从参考图提取主色、辅色、背景色、文字色，映射到色板层
2. 识别参考图使用的字体，匹配相近的 Google Fonts
3. 提取圆角大小、阴影强度、间距密度等风格参数
4. 参考图的"感觉"比"精确值"重要，按画布尺寸调整后再填入 JSON

## 六、不确定时

- 不要用"我觉得好看"来论证设计决策，而是说"参考了 XX 作品，提取了主色 XXX，是否合适"
- 对功能假设标注存疑，让人类确认
- 不确定风格方向时，问人类要参考

---

## 工作流程

```
人类提供参考 → 读现有 tokens.json 结构 → 修改数据层 JSON
→ 自检 → 人类审查 → 确认后修改渲染层 → 截图对比验证
```
