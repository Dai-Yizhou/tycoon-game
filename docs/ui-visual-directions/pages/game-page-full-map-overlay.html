游戏页全地图 HUD 覆盖层对比稿

地图铺满整个游戏窗口，所有功能以 HUD 覆盖层叠加。系统通知并入聊天区，当前格详情固定为地图悬浮卡片。基线 1440×900 横屏。

HUD 控件清单与图层归属

每个控件只消费语义 ViewModel，不直接读取游戏核心对象或 Socket。按钮可用状态由集中式状态矩阵计算，业务模块不直接写 disabled。主题令牌来自 DesignAdapter 快照。

顶部 HUD 状态层

row 1 · 9%
  • player-badge 头像 + 名称 + 队伍标签
  • value-pill 财产 / 信用值 / 备选数值（如环保值）
  • cycle-indicator 昼夜状态 + 剩余时间
  • notice-bell 聊天入口 + 系统通知未读计数

耦合约束：数值只从 Store.playerStats 读取；昼夜从 Store.cycle 读取。

全屏地图底层

col 1 · row 2-3 · 72%
  • board-canvas 棋盘格子、连线、棋子（Canvas 2D 渲染）
  • zone-tag 当前区域名称 + 繁荣度百分比
  • path-highlight 多岔路可选路径高亮（仅路径选择态）

耦合约束：地图由 ViewModel.board 驱动；UI 不解析地图 JSON 内部结构。

悬浮信息层

col 2 · row 2-3 · 18%
  • tab-bar 当前格 / 玩家 / 聊天 三页签切换
  • cell-card cell-hover-card 当前格详情悬浮卡片
  • player-list 在线玩家排行（名称、财产、位置）
  • chat-feed 频道消息流（系统 / 队伍 / 区域）
  • chat-input 消息输入框 + 发送按钮

耦合约束：详情卡从 Store.hoverCell 读取；聊天与系统通知从 Store.chat 读取。

底部 HUD 行动层

col 1 · row 3 · 12%
  • dice-btn 掷骰主按钮（冷却禁用态）
  • act-btn 上下文动作：购买 / 升级 / 修缮 / 传送 / 合租
  • item-tray 道具槽：查封令 / 复活令（计数角标）
  • path-prompt 路径选择按钮组（仅多岔路态）

耦合约束：按钮 disabled 由 actionMatrix(state) 集中计算；点击发 client.* 请求。

设计决策记录

为何选方案A"全屏地图底层"
开放地图与非环形路径是本游戏的核心空间特征。方案A让地图占据 72% 视觉面积，保证玩家在任何时刻都能看到棋盘全貌与自身位置。顶部 HUD 状态层、悬浮信息层、底部 HUD 行动层分别从三个边缘包裹地图，不切割地图主体。方案B"控制台账本"的右侧固定面板会压缩地图纵深；方案C"区域分屏"的左右对称栏位分散地图焦点。
控件为何按四区域编排
对应玩家在回合中的四种认知焦点：我是谁（顶部 HUD 状态层：身份与数值）、我在哪（全屏地图底层：空间定位）、这是什么（悬浮信息层：当前格详情）、我能做什么（底部 HUD 行动层：可用动作）。四个区域与 SPEC 中 FR-2（掷骰移动）、FR-3~FR-9（格子类型交互）、FR-10~FR-12（数值系统）、FR-17~FR-18（聊天通知）的映射关系清晰。
底部 HUD 行动层为何覆盖地图边缘
行动栏不是常驻固定栏，而是"浮动覆盖"——它只在玩家需要做决策时浮现在地图底部边缘。待掷骰态下行动栏极简（仅掷骰按钮 + 道具槽），地产决策态下切换为购买/拍卖/跳过，路径选择态下切换为路径按钮。这种设计避免行动栏在无操作时浪费屏幕空间。实现上使用 grid-row: 3; z-index: 1，地图 grid-row: 2/4 跨越行动栏区域，行动栏叠加在地图底部。
悬浮信息层为何用三页签而非全部展开
18% 宽度不足以同时展示当前格详情、玩家列表和聊天。三页签（当前格/玩家/聊天）让玩家按需切换，降低信息密度压力。默认激活"当前格"页签——因为玩家最常需要的信息是"我停在了什么格子上"。聊天页签底部保留输入框，确保切换到聊天后可直接发送消息。
三种状态预览的选择依据
待掷骰（A）是最高频状态，验证基础布局与默认控件。地产决策（B）验证上下文动作切换——底部 HUD 行动层从掷骰变为购买/拍卖/跳过，同时浮出事件提示。路径选择（C）验证非环形地图的核心交互——多岔路高亮与路径对比信息。三种状态覆盖了 SPEC FR-2（掷骰）、FR-3（地产购买）、FR-1（连线路径）三个最核心的功能需求。
主题令牌与低耦合
三帧均使用东北走廊主题（.theme-northeast）展示。实际运行时，主题由 DesignAdapter 根据玩家所在区域动态切换（东北/深南/中西部/远西四套令牌）。所有控件颜色引用 --gp-* 变量而非硬编码值，确保主题切换时全部控件同步变化。控件不直接调用 DesignAdapter，而是接收 Store 下发的 token 快照。
按钮状态矩阵
所有 disabled 状态由集中式 actionMatrix(state) 函数计算，输入为游戏状态枚举（idle / rolling / moving / property-decision / path-selection / jailed / bankrupt），输出为各按钮的可用性。业务模块（如 MovementHandler）不直接写 button.disabled = true，只更新 Store 状态，UI 层响应状态变化自动更新按钮。这避免了分散的状态写入导致的按钮闪烁与不一致。
