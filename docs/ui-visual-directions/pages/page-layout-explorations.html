01 / 先定边界

低耦合布局契约

页面只呈现语义 ViewModel；地图由数据驱动，非环形路径由连接线定义。

服务端是唯一权威。UI 只消费 Store / ViewModel；UIUpdates 负责 DOM 更新，Canvas 负责棋盘、棋子与连线。事件流保持单向可追踪。

Server Snapshot权威状态快照
ViewModel语义化、可呈现数据
Controls / Regions区域与控件编排
DOM + CanvasUIUpdates 与画布分工
控件 不读取游戏核心对象页面 不直接解析地图 JSON主题 只来自 DesignAdapter事件流 client.rollDice / client.choosePath → server.playerMoved → Store → UI
02 / 四页一组

三套横屏布局方案

缩略框仅表达版块关系；全部为 16:10 横向宽屏，移动横屏仅作适配标注。

A

地图舞台 推荐方案

地图永远第一视觉层：顶部状态、右侧信息、底部行动覆盖地图边缘。

最贴合开放地图和非环形路径的空间阅读。

控件编排规则

Canvas 区域
棋子、格子、连线只在地图舞台出现。
DOM 区域
选项卡与数值框进入右侧信息带。
行动区域
掷骰按钮与路径选择进入底部行动带。
反馈区域
通知条贴近顶部状态带；事件弹窗以中央为锚点。
B

控制台账本 备选

信息与操作固定在右侧，地图保持左侧主工作区。

强调持续读数与策略决策，牺牲部分漫游纵深。

控件编排规则

左侧地图
棋子、格子、连线固定在地图工作区。
右侧账本
选项卡、数值框、事件弹窗进入信息与操作区。
顶部跨栏
通知条与全局状态集中；行动控件留在右栏。
页面边界
欢迎与中止页沿左右叙事 / 决策二分组织。
C

区域分屏 备选

中央地图被左右悬浮信息区包围，顶部时代轴与底部行动轴跨栏。

强化时代与时间变化，但对称栏位会分散地图焦点。

控件编排规则

中央地图
棋子、格子、连线只在中央地图层出现。
左右状态栏
这里只表达悬浮信息区域，不画具体组件。
顶部 / 底部
通知条进入时代带；行动控件进入底部行动区。
事件反馈
事件弹窗位于中央地图上方，不改变地图主层。
03 / 交付前检查

低耦合核对

布局是外壳；状态矩阵集中计算按钮状态，业务模块不直接写 disabled。

通过
页面只依赖语义 ViewModel

不把服务端对象泄露给展示层。

通过
控件只依赖 DesignAdapter token snapshot

主题边界清晰且可替换。

通过
Canvas / DOM 共用同一主题快照

棋盘与页面不会各自漂移。

禁止
页面读取地图 JSON 内部结构

地图只通过语义 ViewModel 暴露。

禁止
组件直接调用游戏核心或 Socket

事件经 Store 与集中式更新流转。

禁止
业务模块直接写按钮 disabled

由集中式状态矩阵计算可用状态。
