# Tycoon 游戏 UI 重构执行计划

## 摘要

本计划将 UI 样式收敛为单一令牌来源，并经适配层同时供给 Canvas 与 DOM。所有设计系统、适配器和 UI 迁移均在 `ui-Dai` 开展；`dev-Dai` 的游戏页面改动仅在收到明确指令后同步并适配。每次只迁移一个可验证单元，默认主题保持现有体验稳定，新主题单独验收。

## 已核实背景

- 已读取设计方案、任务清单、验证清单、协作指南和参考资源。
- 已拉取协作规则，并会在每个迁移阶段开始前执行远端同步检查。
- 已读取桌面副本的产品说明、玩家手册、客户端主界面与手绘图稿。
- 游戏是 2D 俯视、多人实时、持续运行的开放世界大富翁。格子由地图数据定义，连接线形成可分岔的自由路径，而非固定环形棋盘。
- 已确认的主要系统包括地产、投资、事件、交通传送、纪念碑、昼夜时区、区域繁荣度、信用、天赋、组队、道具与时代切换。
- 已确认客户端的核心表现层由 Canvas 棋盘渲染器与 DOM HUD/弹窗共同构成；已定位棋盘、格子、连接线、棋子、昼夜、HUD、骰子与关键弹窗模块。
- 手绘图稿提出路径随地图变化、统一色彩体系、圆头小人棋子、起始页地图剪影和岔路指引。它是视觉方向依据，不是需要逐像素复刻的成稿。
- 桌面副本当前处于 `Dais_branch_1`，其远程引用未显示 `ui-Dai`。在确认 `ui-Dai` 实际来源前，桌面副本只用于调研和视觉验证，不在其上进行 UI 迁移。

## 修订后的边界

### 数据层

- 使用 DTCG 兼容的令牌文件，区分基础色板、语义令牌、组件令牌和主题覆盖。
- 图像、纹理、动画和粒子参数可以分文件维护；主题只覆盖差异。
- 数据文件只包含可序列化值和引用，不包含条件、循环、插值或布局逻辑。

### 适配层

- 对外暴露 token 查询、引用解析、主题合并、CSS 变量注入和 Canvas 调色板导出。
- 解析错误必须显式报告：未知令牌、循环引用、非法主题覆盖、资源缺失。
- Canvas 导出为稳定的语义调色板接口，不让渲染器依赖 JSON 的内部路径。

### 渲染层

- 禁止直接硬编码视觉令牌：颜色、字体、视觉尺寸、圆角、阴影、动画时长、资源路径。
- 允许渲染算法、坐标计算、物理模拟和性能敏感的几何参数保留在渲染层；这些值必须有明确的逻辑理由，不伪装成视觉令牌。
- 默认主题的迁移验收是功能与视觉基线稳定；手绘等新主题按设计目标验收，不要求与旧界面逐像素一致。

## 视觉方向与决策点

当前探索不再组合成完整游戏页，而是将决策拆为视觉基础、单控件与页面骨架三个维度。已否决“潮流街头”作为候选方向，原因是色彩能量和城市感过强，遮蔽了休闲、自然、可长期游玩的基本体验。

- 花园棋盘：奶油白、草绿、天空蓝、番茄红、日光黄；MiSans/PingFang；2px 深墨描边和圆头路径。推荐优先细化，兼顾 `florr.io` 式直接可读性与大富翁地图的自然区域感。
- 彩色地图册：暖纸色、湖蓝、橘红、嫩芽绿、紫罗兰；Noto Sans SC/PingFang；蓝灰细线和地图册质感。适合突出时代切换、路线探索和事件叙事。
- 果冻棋局：浅雾蓝、青柠、珊瑚、葡萄紫、蜂蜜黄；HarmonyOS Sans/PingFang；深蓝粗描边和圆润路径。适合更轻快的多人互动与显性状态反馈。

三套方案均延续图稿中的圆头小人棋子、自由路径和明确岔路指引，但不复制具体构图或视觉细节。

### 1900 年地域主题原则

1900 年美国的地域差异将作为主题覆盖的材料与印刷语法来源，而不会改变玩法层级或对局规则。棋子、路径、格子分类、岔路指引、信息优先级和交互模式应跨主题保持一致；地域只覆盖色彩、字体、边框、阴影和微妙的材料暗示。

- 共用棋子：基础形态为高梯形（上底 16px、下底 26px、高 30px）上接圆形头部（直径 22px），不画脚/腿，整体约 30×56px，3px 深墨轮廓。采用 `box-sizing: border-box`，躯干填充从边框内侧开始，禁止 fill 覆盖或挤压 border，保证头部与梯形边框视觉等宽。变体包括基础型、纹理型（斜线呢料纹理）、昼型、夜型（暗化配色 + 暗金亮边）、选中态（外扩光环）。玩家色仅填充躯干，头部为浅色或深灰。三色样本：红 #C0392B、蓝 #2C5F8D、绿 #4A7C3F。
- 棋子动作变式：站立（默认待机）、左倾/右倾 8deg（移动前摇）、前探 3px（方向选择）、后仰 3px（受阻/暂停）、举牌（12×10px 外置信息牌）、聚拢压缩 2px（组队/确认）、跳跃上移 6px 且保留 6px 空隙（成功反馈，不画脚）。动作 `transform-origin` 固定为底部中心，变式不改变基础尺寸；纹理只进入内填充层，建议 45deg 细斜线、透明度 12-16%。
- 共用连线：单根、圆端、低装饰自由路径。2px 表示地图线（浅灰）、3px 表示当前路径（深墨）、4px 表示关键路径（强调色）；岔路只有 8px 实心圆节点和简单三角箭头，不使用轨道、双线或道路阴影。
- 东北走廊（纽约/波士顿/费城）：砖墙棕红、沥青灰黑、氧化浊绿、电车火花橘红；纵向拉伸矩形、极细平行双线、密集机械卷草纹；宽体粗衬线 + 紧凑无衬线；砖墙砂砾与百叶窗光影。动态：50ms 快速微振、跳跃式跳转。
- 深南腹地（新奥尔良/亚特兰大/棉花带）：褪色木白、苔藓灰绿、铁锈棕、棉布褪色蓝；铁艺细卷曲、十字格栅、大圆角药丸；手写衬线斜体 + 松散功能字；木纹晒裂与亚麻经纬。动态：极长 ease-out、延迟 +50-80ms、缓慢弹起。只取材料与建筑语法，不得暗示或装饰任何压迫历史。
- 中西部大平原（芝加哥/圣路易斯/堪萨斯城）：干草黄、碎石灰、赭石棕、检疫品蓝；单线直角 3-4px 粗边框、对角斜线填充；极粗无衬线黑体 + 等距方块数字；砂纸颗粒与拉丝金属。动态：段落阻尼、硬回弹、匀速指针跳变。
- 远西边疆（旧金山/西雅图/淘金残迹）：浓雾灰白、红杉红褐、灯笼朱红、硫磺绿；中式窗棂冰裂纹、维多利亚尖顶、2-3 度斜切；细长衬线电报体 + 方正汉字骨骼；海雾柔光与帆布编织。动态：10 秒水平摇摆、余震瞬间抖动。

确认默认方向后，另外两套保留为独立主题候选，不直接混入默认色板。

## 分期实施

### 阶段 0：仓库审计与基线

1. 同步 `agent-rules`，检查规则更新。
2. 成功检出 `ui-Dai` 后，读取包管理脚本、入口、渲染器、DOM 组件和现有设计图稿。
3. 产出硬编码样式审计表、现有资源表、截图基线和模块依赖图。
4. 将 `dev-Dai` 页面结构视为外部依赖，不直接修改。

验收：实际文件、入口、类型和调用关系已核实；每项迁移对象都能定位其渲染入口与回归截图场景。

### 阶段 1：令牌与契约

1. 建立默认主题的基础、语义、组件、图像、动画令牌。
2. 先覆盖已审计到的值，不以“猜测所有样式”为目标。
3. 写入令牌解析与主题覆盖的边界测试。
4. 提交仅包含数据层的独立变更，供视觉确认。

验收：引用无断裂、无逻辑代码、默认令牌可被解析、主题覆盖只包含差异。

### 阶段 2：适配器与应用入口

1. 建立适配器、Canvas 调色板类型和初始化入口。
2. 应用启动时注入 CSS 变量；主题切换后通知 DOM 和 Canvas 重绘。
3. 对令牌缺失、循环和资源错误提供开发期诊断。
4. 为查询、解析、注入和主题切换编写测试。

验收：DOM 与 Canvas 在同一主题下读取同一语义颜色；切换和切回默认主题均稳定。

### 阶段 3：Canvas 逐件迁移

按真实依赖顺序迁移棋盘、格子、棋子、连接线、遮罩和粒子相关渲染器。每迁移一个渲染器：

1. 只替换已审计的视觉令牌。
2. 运行项目已有类型检查与测试。
3. 截图对比默认主题。
4. 记录性能与视觉差异；未经确认不扩大迁移范围。

验收：默认主题无阻断性视觉回归，渲染器不再直接声明视觉令牌。

### 阶段 4：DOM UI 分组迁移

按 HUD、弹窗、操作按钮、侧栏与通知、其他状态组件分组迁移。每组独立提交并验证交互状态：默认、悬停、焦点、禁用、加载/空/错误（适用时）。

验收：样式由 CSS 变量或适配器承接；关键操作依旧可达、可读、可键盘聚焦。

### 阶段 5：主题与跨分支适配

1. 默认主题稳定后再创建深色主题；手绘主题作为明确批准后的可选工作。
2. 收到“同步 `dev-Dai`”明确指令后，先拉取两分支差异，再将页面变动同步到 `ui-Dai`。
3. 仅做必要的 UI 结构与令牌适配，不重写核心游戏逻辑。
4. 冲突、语义不明或影响游戏规则时暂停并请求确认。

验收：主题切换同时更新 Canvas 与 DOM；同步改动在 `ui-Dai` 经类型检查、测试和关键界面截图验证。

## 每次变更的固定检查

- 开始前：同步工作规则、检查当前分支与工作区、读取实际调用链。
- 数据层：JSON 语法、引用解析、无逻辑、令牌影响范围。
- 适配与渲染：项目既有类型检查、相关测试、实际入口接入。
- 视觉：默认主题基线截图；新主题目标截图；窄屏与常用桌面宽度检查。
- 提交前：只包含本阶段相关变更，不合并稳定分支，不推送或合并未获明确指令。

## 风险与处理

- 主题切换造成 Canvas 与 DOM 时间差：适配器提供统一主题版本号，渲染器在同一帧或下一可用帧读取新版本。
- 令牌过度细分：优先语义令牌，只有确有独立生命周期的视觉差异才落到组件令牌。
- 资源加载失败：保留无纹理的可读降级表现，记录错误但不阻断核心对局。
- `dev-Dai` 页面结构漂移：同步前审阅差异并只做最小适配；无法判断的游戏语义不自行推测。

## 待确认

1. 分别选定色彩/字体/线条、控件语言、页面骨架的优先方向，或说明可混合的边界。
2. 选定默认方向后，以手绘图稿的路径与棋子原则校正色彩、字体、地图线条和状态动效。
3. 手绘主题是否属于本轮重构范围，还是默认主题稳定后的独立迭代。
