# 人类开发者/设计师指南：如何与 AI 协作设计

> 本文档面向人类开发者或设计师，说明如何通过设计系统与 AI 高效协作，让 AI 产出**符合你期望**的设计，而不是"AI 味"的奇怪东西。

---

## 核心原则：AI 需要参考，而不是指令

AI 是一台"风格匹配引擎"，不是"品味过滤器"。

| AI 做不好的事 | AI 能做好的事 |
|--------------|-------------|
| 自己判断"好不好看" | 模仿给定的风格 |
| 创新风格（容易变成"AI 味"） | 在已有风格内做微调 |
| 理解"高级感"、"大气"这类抽象描述 | 从参考图中提取具体颜色/尺寸 |
| 判断设计是否符合品牌调性 | 严格遵循给定的 token 值 |

**结论：不要期待 AI 自己创造好看的风格。你要给 AI 参考，让 AI 执行。**

---

## 如何提供参考

### 最好的方式：截图 + 描述

```
这是参考截图：[附截图]
我想要类似的风格，具体来说：
- 颜色：温暖的米色和棕色为主，避免冷色
- 字体：圆润的手写体
- 圆角：大圆角（看起来友善）
- 整体感觉：像手绘棋盘游戏，像《动物森友会》那种治愈感
```

AI 会从截图提取色板、匹配字体、提取风格参数，然后映射到设计系统的 JSON 文件中。

### 最基础的方式：文字描述 + 关键词

如果你没有截图，用**具体的关键词**，避免抽象词汇：

| 抽象词汇（AI 听不懂） | 具体词汇（AI 能执行） |
|---------------------|---------------------|
| "要高级感" | "参考 XX 游戏的配色，主色 xxx，辅色 xxx" |
| "要温馨" | "米色背景，暖棕色边框，大圆角，手写体" |
| "不要 AI 味" | "避免渐变，避免玻璃拟态，用纯色填充，用硬阴影" |

## 如何通过设计系统约束 AI

设计系统不仅是"让 UI 好看"的工具，更是**约束 AI 的护栏**。

### 方法 1：在色板文件中锁定色板

AI 倾向于使用"鲜艳的蓝色"和"科技感渐变"。如果你在色板中只定义暖色系，AI 的修改范围就被限定了。AI 新增颜色时，只能从已有的色值附近选择，不可能突然引入荧光粉或科技蓝。

### 方法 2：在组件样式文件中锁定组件结构

定义好所有格子类型的样式结构后，AI 新增格子类型时自然会复制已有结构，只替换颜色引用——保持风格一致。

### 方法 3：使用主题文件隔离试验

如果 AI 想尝试新风格，不要直接修改主设计文件，而是创建一个新主题文件。切换主题验证效果，满意后再合并到主设计系统。

```
themes/
├── dark.json           ← 只覆盖颜色
├── experimental.json   ← AI 试验新风格的地方
└── handdrawn.json      ← 手绘风格
```

## 如何审查 AI 的设计输出

### 审查数据层（JSON 修改）

| 审查项 | 典型问题 |
|--------|---------|
| 色板一致性 | AI 突然加入荧光色 |
| 引用链完整性 | 引用了不存在的色值名 |
| 逻辑注入 | JSON 中是否有 if/else/函数 |
| 过度设计 | 不必要的渐变/阴影/装饰卡片 |
| 冗余 | 可以用现有 token 表达的样式 |

### 审查渲染层（代码修改）

| 审查项 | 典型问题 |
|--------|---------|
| 硬编码 | 新代码中仍有直接写死的颜色值 |
| 适配器使用 | 新组件未通过 adapter 查询样式 |
| 视觉差异 | 截图对比改造前后不一致 |

## 如何描述"感觉"（让 AI 理解你的审美）

### 用"像 XX"代替"高级"

| 不好的描述 | 好的描述 |
|-----------|---------|
| "要高级感" | "像《纪念碑谷》那种低多边形、柔和的粉彩风格" |
| "要温馨" | "像《动物森友会》的暖色木纹和圆润按钮" |
| "要简洁" | "像 Apple 官网的留白多、纯色、无装饰" |

### 用"具体值"代替"感觉"

| 不好的描述 | 好的描述 |
|-----------|---------|
| "颜色暗一点" | "主色亮度降低 20%" |
| "圆角大一点" | "圆角改为 12px" |
| "字体可爱一点" | "字体从 Inter 换成手写体" |

## 与 AI 协作的工作流

```
你（人类）                        AI
──────────────────────────────────────────────────
1. 提供参考截图 + 描述
   ──────────────────────→    2. 读取现有设计文件
                              3. 从参考图提取色板/字体/参数
                              4. 修改设计文件 + 自检
   ←──────────────────────    5. 提交修改 + 说明变更依据

6. 审查修改
   ├── 满意 → 确认
   └── 不满意 → 给反馈（如"把主色改为暖色系"）
        └───→ AI 再次修改

7. 确认后，授权 AI 修改渲染层
   ──────────────────────→    8. 替换硬编码为 adapter 查询
                              9. 截图对比验证
   ←──────────────────────    10. 完成
```

## 常见问题

### Q: AI 改出来的颜色还是不对怎么办？

提供更精确的约束：
```
"所有颜色的饱和度降低 30%，亮度提高 10%"
"不要使用蓝色和紫色，只保留暖色系"
"参考这个色板：xxx"
```

### Q: 如何防止 AI 一次改太多？

告诉 AI 限制范围：
```
"只改色板部分，其他不变"
"先改 CellRenderer，不改其他文件"
```

引自 [agent-rules work-principles.md](https://github.com/Dai-Yizhou/agent-rules/blob/main/rules/work-principles.md)：**"以批量乱改为耻，以分步迭代为荣"**。

### Q: 如何确保 AI 的设计风格长期一致？

1. 把设计文件纳入版本控制，每次修改有 diff 可追溯
2. 不允许 AI 在没有参考的情况下新增颜色/组件
3. 定期审查设计文件的变更历史
