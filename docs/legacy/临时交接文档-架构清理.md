## 六、上一轮审计发现（已交叉核实）

### 高风险/明确问题

1. **`client.useItem` 协议漂移**
   - shared 协议使用 `targetCellId`、`targetPlayerId`。
   - client 新 ModalSystem 也发送这两个字段。
   - server 旧 ItemHandler 使用 `cellId`、`playerId`。
   - 本次彻底删除系统，因此应删除整个事件和实现，而不是做兼容适配。

2. **客户端旧 ItemSystem 直接修改服务端权威状态**
   - 旧实现本地扣道具、信用、金钱、状态和位置。
   - 新 ModalSystem 只发送请求，但本次系统整体删除，因此相关 UI 与请求均删除。

3. **重复 `client.ping` 注册**
   - `SocketManager.registerCoreHandlers()` 注册 ping。
   - `HandlerRegistry.registerForSocket()` 调用 `handlePing(socket)` 再注册一次。
   - 删除 HandlerRegistry 里的重复注册，保留 SocketManager 版本。

4. **旧 HUD 与旧 Hooks 并存**
   - 新入口是 `GameHudShell`。
   - 旧 `hud/*`、`usePlayerState.ts`、`useMovement.ts` 仍存在并被旧测试/类型引用。
   - 用户已明确“全部清理”，解除依赖后删除。

5. **`NotificationManager` 未接入**
   - 没有 `new NotificationManager()` 或运行时业务调用。
   - 当前可保留为通用基础设施，但文档必须明确“未接入”；若其唯一功能是三个系统通知，则删除对应方法或整个模块。

6. **客户端破产语义耦合**
   - `GameLogic.checkBankruptcy()` 可能在客户端本地余额为零时直接发送 `client.bankruptRestart`。
   - 必须重新阅读调用链，不能让本地余额判断替代服务端破产事件。

### 文档过时点

- `docs/architecture/API.md` 的 `client.useItem` 字段已过时；本次删除整个事件后应移除章节。
- `API.md` 聊天“全局广播占位”已过时，实际是 ChatManager + global/team/region 分发。
- `docs/architecture/FILE_MAP.md` 需要说明 `registerHandlers()` 只创建 registry，`app.ts` 是唯一 connection 注册点，业务由 `registerForSocket()` 注册。
