# 大富翁.io - 产品需求文档

## Overview
- **Summary**: 大富翁.io是一款结合经典大富翁玩法与io游戏大世界概念的多人在线网页游戏。与传统大富翁单一追求财富的目标不同，本游戏设计了**财产、信用值、备选数值**三大平行数值体系，玩家可以选择不同的发展路径达成胜利。游戏支持地图编辑器定义的**完全自定义棋盘数据结构**，每个时代的棋盘都可以有独特的格子类型、属性和规则。玩家在持续运行的开放世界中掷骰前进，购买地产、组队协作、使用道具，通过多元策略与社交互动达成目标。
- **Purpose**: 打破传统大富翁游戏的封闭棋盘与单一财富目标，打造一个持续运行、多人实时互动、玩法多元的开放世界大富翁体验。玩家可以自由进出游戏，选择不同的发展路线（财富流、信用流、特殊目标流），与其他玩家组队或竞争，在自定义棋盘上探索丰富的策略深度。
- **Target Users**: 休闲游戏玩家、策略游戏爱好者、社交型玩家、喜欢多人在线互动游戏的用户、自定义地图创作者。

## Goals
- 实现三大平行数值体系：财产、信用值、备选数值，支持多元胜利路径
- 支持地图编辑器定义的完全自定义棋盘数据结构，格子属性和规则由地图数据驱动
- 构建io式大世界：多人实时在线、持续运行的游戏世界
- 实现8种基础格子类型与可扩展的自定义格子属性
- 设计道具系统：查封令、复活令等，支持未来扩展
- 实现昼夜时区与区域繁荣度系统，增加游戏深度
- 提供社交与组队系统：队伍合并/分离、共享数值、多频道聊天
- 支持多时代棋盘切换与结算机制
- 提供账号系统与离线状态保存
- 支持多语言国际化
- 天赋系统允许玩家自定义启用的数值字段和游戏机制

## Non-Goals (Out of Scope)
- 移动端原生App（仅网页版）
- 3D图形渲染（2D俯视视角）
- 跨平台账号同步（初期仅支持单平台）
- 硬编码固定的游戏规则（规则由地图数据和天赋动态决定）
- 语音聊天与视频聊天系统
- 广告系统与第三方广告接入
- 付费商城与付费道具（游戏为免费游玩，道具仅通过游戏内获取）

## Background & Context
- **游戏设计参考**: 经典大富翁棋盘玩法 + florr.io式大世界概念 + 多元数值目标设计
- **地图编辑器**: 已有的地图编辑器（位于 `map_editor_v01.01/`）定义了**完全自定义的格子数据结构**。该编辑器为**只读参考工具**（提供数据格式定义与示例，如 `format_example.json`、`output_example.json`），游戏引擎动态解析其导出的地图数据，不依赖固定的字段列表。格子属性不是硬编码的，而是由属性模板（template）定义，模板决定每个格子有哪些属性、属性的类型和编辑方式。
  - 内置字段：`id`、`x`、`y`、`destinations`（连线）
  - 自定义字段：完全由模板定义（如 `name`、`type`、`price`、`rent`、`level`、`behavior`、`icon` 等）
  - 编辑器支持：文本、数字、布尔、数组（数字/字符串）等类型
  - 支持从文件夹选择文件的属性（如 `behavior`、`icon`）
- **AI Bot 测试系统**: 项目包含独立的 AI Bot 系统（位于 `ai-bot/`），作为**开发与测试工具**（非游戏功能）存在，用于游戏服务端 Bug 检测与平衡性评估。详见 FR-24。
- **UI设计**: 手绘UI草图包含开始界面（剪影下落出现地图）、玩家棋子小人（三种样式）、棋盘指引线等元素
- **技术选型**: 全栈网页游戏，前端使用Canvas/SVG渲染棋盘，后端使用Node.js + WebSocket实现实时多人互动
- **代码规范**: 注重可维护性和可扩展性，模块化设计，数据驱动架构，便于与其他开发者和AI协作

## Functional Requirements

### FR-1: 自定义棋盘与数据驱动渲染
- 支持加载地图编辑器导出的JSON地图数据
- 动态解析格子的自定义属性（由地图模板定义），不硬编码字段
- 内置字段处理：id、坐标、连线（destinations）
- 自定义字段的类型支持：文本、数字、布尔、数字数组、字符串数组
- 支持8种基础格子类型（type字段）：property（地产）、empty（空格）、event（事件）、investment（投资）、transport（交通枢纽）、monument（纪念碑）、start（起点）、jail（监狱）
- 格子间通过连线定义移动路径（支持非环形的开放地图）
- 支持多时代棋盘，每个时代使用不同的棋盘地图和不同的属性模板
- 棋盘渲染支持缩放和平移
- 玩家棋子在棋盘上按步数移动动画
- 行为文件（behavior）机制：格子可关联行为脚本，由地图定义触发逻辑

### FR-2: 掷骰与移动系统
- 玩家点击掷骰按钮进行掷骰
- 掷骰有冷却时间，防止连续操作
- 骰子结果随机（1-6步）
- 玩家棋子从当前位置沿连线方向移动对应步数
- 多岔路口的路径选择（由地图定义或玩家选择）
- 到达目标格子后触发对应格子的事件和行为
- 监狱状态下大幅延长掷骰冷却

### FR-2.1: 玩家视野系统
- 棋盘完全可见，无视野遮罩/雾化系统
- 相机平滑跟随玩家移动
- （原设计的视野遮罩与雾化效果未实现；如未来需要可扩展）

### FR-3: 地产格系统（property）
- 无主地产：玩家经过时可选择购买（价格由price字段定义）
- 主人经过：可升级建筑等级（若未升满，升级费用由upgradeCost定义）
- 他人经过：向地产所有者支付租金（租金由rent数组按等级取值）
- 合租机制：多名玩家可共同持有同一地产，按投资比例持股
- 每过一个昼夜：计税一次（税率由棋盘配置定义）
- 地产的具体数值完全由地图数据驱动

### FR-4: 事件格系统（event）
- 玩家经过时随机触发事件
- 事件可针对单玩家或区域
- 事件触发概率受玩家信用值影响
- 事件类型包括：获得/损失各数值字段、获得道具、改变信用值、触发区域效果等
- 事件具体效果由事件配置/行为文件定义，支持自定义

### FR-5: 投资项目格系统（investment）
- 无主状态：玩家可购买
- 他人经过：可选择合租（按比例持股）
- 被事件触发：对投资项目所有者产生效果（收益或损失）
- 投资数值由地图数据定义

### FR-6: 交通枢纽系统（transport）
- 玩家经过时可付费传送至指定格子（费用由地图定义）
- 每过一个周期（昼夜），交通枢纽变更目的格子
- 支持多个交通枢纽之间的网络
- 目的地列表由地图的destinations字段定义

### FR-7: 纪念碑系统（monument）
- 玩家可修缮纪念碑，消耗财产
- 修缮纪念碑增加玩家信用值和区域繁荣度
- 一段时间未修缮则降低区域繁荣度
- 修缮费用和效果数值由地图定义

### FR-8: 起点系统（start）
- 游戏开始时玩家从起点出发，获得启动资金
- 每次经过起点时发放补充资金
- 起点处可勾选天赋选项
- 启动资金和补充金额由地图定义

### FR-9: 监狱系统（jail）
- 踩中监狱格子则进入监狱状态
- 监狱期间：大幅延长掷骰冷却、禁用收取费用、扣除信用值
- 离开监狱后恢复正常状态
- 监狱时长和惩罚数值由地图定义

### FR-10: 财产数值系统
- 玩家拥有财产（金钱）数值（必选字段，始终启用）
- 破产机制：财产持续为零或以下达到服务端阈值后进入破产；破产期间保留队伍、地产、投资和持股，仅允许显式重开操作
- 合租持股比例：按后到玩家支付金额与原主人购买金额的比例计算
- 财产的具体作用和数值由棋盘和天赋配置决定

### FR-11: 信用值数值系统
- 玩家拥有信用值数值（可选字段，由天赋决定是否启用）
- 信用值随欠款增多而降低
- 信用值影响事件概率、部分道具效果
- 信用值是与财产平行的核心目标，而非附属系统
- 高信用值玩家可获得独特优势（如好事件概率更高）

### FR-12: 备选数值字段系统
- 与财产、信用值平行的第三类（及更多）数值（可选字段，由天赋和棋盘定义）
- 每个棋盘可定义不同的备选数值（名称、机制、用途完全自定义）
- 机制相对简单，主要受玩家所有的地产数值和事件格事件影响
- 可参与时代结算，具体由棋盘定义
- 支持多个备选数值字段，由棋盘模板动态扩展
- **备选数值也可以对区域设置**（不只针对玩家，也可针对棋盘上的区域）
- 示例：**环保值** —— 受到玩家购买的地产类型、投资项目、事件格效果的影响
  - 例如：购买污染类地产会降低环保值，购买环保类地产会提升环保值
  - 某些事件会奖励/惩罚环保值
  - 环保值可影响区域繁荣度、特殊事件触发等
- 其他备选数值示例（供地图作者参考）：声望、文化值、科技点、幸福度等
- 备选数值可以是某些棋盘的主要目标或评价维度

### FR-13: 天赋系统与自定义玩法
- 在起点处勾选启用天赋
- 可增减数值字段：财产为必选字段，可选启用信用值、备选数值等
- 可启用/禁用特定游戏机制：道具系统、组队系统等
- 天赋值通过成就系统获得，用于解锁和启用天赋
- 不同天赋组合带来不同的游戏体验和策略路径
- 天赋选择影响游戏目标和评价维度

**天赋系统选项示例**（不限于此，可扩展）：
- **视野**：玩家视野范围（始终小于棋盘，玩家只能观察周边的有限格子）
- **信用值启用开关**：是否启用信用值数值系统
- **备选字段启用开关**：是否启用备选数值字段（如环保值）

### FR-14: 繁荣度与时区系统
- **区域繁荣度**：由纪念碑和时区调节驱动
- **时区系统**：棋盘按时区划分（类似真实世界时区），每个格子属于某个时区
- **昼夜循环**：时区处于夜晚时降低区域繁荣度，白昼时恢复
- 繁荣度影响该区域内的地产收益、事件概率等
- 时区划分和昼夜周期由地图配置定义

### FR-15: 道具系统
- **查封令**：禁用目标格子的任何操作（收租、升级等），短时间后恢复；使用者降低信用值
- **复活令**：远程使用，复活破产玩家，增加信用值
- 道具通过事件格获取，较为稀有
- 玩家持有道具有数量上限
- 道具系统支持扩展，未来可增加新道具
- 道具效果可影响多种数值字段

### FR-16: 组队系统
- 单个玩家视为一个队伍
- 合并队伍需双方在线成员同意，合并后增加信用值
- 分离队伍需其余成员同意
- 离线不解散队伍
- 队内共享所有启用的数值字段（信用值、财产、备选数值等）
- 队内财产共享（平均分配）
- 组队是达成高目标的重要策略路径

### FR-17: 聊天系统
- 聊天分频道：系统频道、队伍频道、区域频道
- 系统消息：游戏事件通知
- 队伍聊天：仅队内成员可见
- 区域聊天：当前区域内玩家可见
- 聊天内容支持显示数值变化通知

### FR-18: 系统通知
- 重要游戏事件通过系统通知提示玩家
- 部分通知支持玩家操作输入（如指定复活令使用对象、选择路径等）
- 通知历史可查看

### FR-19: 成就系统
- 记载玩家的游戏进展（所在棋盘、达成的目标）
- 成就可用于计算天赋值
- 成就跨棋盘保留
- 成就类型包括：财富类、信用类、特殊目标类、社交类等
- **按玩家各方面游戏进展计算天赋值**（综合多维度评价，不单一以财富论）
- **纪念碑与玩家铭记**：在各方面表现出色的玩家被写入纪念碑
  - 例如：最高财产玩家、最高信用值玩家、最佳环保贡献者、最强队伍等
  - 纪念碑是社区荣誉与历史的体现，激励多元发展

### FR-20: 棋盘结算与时代切换
- 每个时代结束时进行结算
- 结算基于所有启用的数值字段（财产、信用值、备选数值等）
- 结算可更新纪念碑状态、天赋值
- 结算后切换到下一个时代的棋盘
- 不同时代的棋盘可以有完全不同的属性模板和规则
- **时代切换对应现实世界 3-6 个月**（长周期结算与重置）
- **时代切换通过类似地图编辑器的可视化应用操作**（专门的管理工具，非游戏内操作）
  - 管理员通过可视化应用选择新地图、配置时代参数、设置结算规则
  - 该工具与地图编辑器复用部分组件

### FR-21: 新手引导系统
- 新玩家首次进入游戏时显示引导教程
- 引导内容包括：基本操作（掷骰、移动）、格子介绍、数值系统说明、组队玩法等
- 引导分步骤、可跳过
- **调试开关**：开发模式下可禁用新手引导（加速开发迭代）
- 调试开关通过环境变量或配置文件启用/禁用
- 调试模式下可快速重置账号、注入测试数据等

### FR-22: 账号系统
- 用户初步熟悉游戏后要求注册账号
- 用户名唯一且固定
- 玩家离线时冻结并保存当前所有数值、地产、位置等游戏状态（若未因时代变更更换棋盘）
- 玩家成就、天赋不因棋盘变化而清除
- 支持游客模式体验，注册后数据迁移

### FR-23: 多语言支持
- 支持多语言切换
- 至少支持简体中文和英文
- 文本内容通过i18n系统管理
- 地图自定义文本（格子名称、描述等）支持多语言（可选）

### FR-24: AI 玩家测试系统（开发工具）
- **定位**：独立的开发/测试工具（`ai-bot/`），**非游戏功能**，用于游戏服务端 Bug 检测与平衡性评估，不作为面向玩家的游戏特性
- **决策引擎**：支持基于规则（rule-based）与基于 LLM 的双决策引擎（`DecisionEngine`、`LLMDecisionEngine`）
- **可视化 AI 玩家**：基于浏览器的可视化 AI 玩家（`BrowserAIPlayer`），模拟真人交互方式接入游戏
- **Web 控制台**：提供 Web 仪表盘（`dashboard/`）用于控制与监控 AI 玩家行为
- **多维评估引擎**：从多维度评估游戏状态与 AI 决策质量（`EvaluationEngine`）
- **Bug 检测**：自动检测游戏服务端 Bug（`BugDetector`）
- **多 LLM 后端支持**：支持 Ollama、Groq、OpenRouter、llamafile 等多种 LLM 后端（`LLMAdapter`）
- **逐 Bot 配置**：每个 AI Bot 可独立配置 LLM 后端、人格（personality）与策略
- **日志导出**：支持 JSON/TXT 格式的日志导出（`logs/`）

## Non-Functional Requirements

### NFR-1: 性能
- 棋盘渲染帧率不低于30fps
- 掷骰响应时间不超过200ms
- 支持单棋盘**千人级**（~1000 名玩家同时在线）
- 页面初次加载时间不超过3秒（宽带环境）
- 地图数据解析高效，支持大地图（200+格子）

### NFR-2: 可用性
- 游戏界面操作直观，新玩家5分钟内可上手
- 支持响应式布局，适配不同屏幕尺寸
- 错误提示清晰友好
- 自定义地图数据错误有友好的提示和降级处理

### NFR-3: 可维护性
- 模块化架构，各功能模块耦合度低
- 代码有清晰的注释和文档
- 遵循统一的代码风格规范
- 类型安全（使用TypeScript）
- 数据驱动架构，游戏逻辑与具体数值分离

### NFR-4: 可扩展性
- 格子类型、道具类型、事件类型支持插件式扩展
- 地图数据格式稳定，向后兼容（忽略未知字段）
- 前后端API设计规范，便于扩展
- 数值字段系统支持动态扩展，不硬编码固定字段
- 行为文件机制支持自定义格子逻辑

### NFR-5: 安全性
- 玩家数据安全存储，密码加密
- 防作弊机制（关键计算在服务端）
- XSS和CSRF防护
- 输入验证和数据校验
- 地图数据加载安全校验，防止恶意数据

### NFR-6: 可靠性
- 服务端崩溃后可恢复，玩家数据不丢失
- 网络中断时客户端有重连机制
- 数据定期备份
- 异常地图数据的容错处理

## Constraints
- **Technical**:
  - 前端：HTML5 + TypeScript + Canvas/SVG渲染
  - 后端：Node.js + TypeScript + WebSocket (Socket.IO)
  - 数据库：MongoDB（文档型，适合灵活的游戏数据结构）
  - 地图数据：完全兼容现有地图编辑器的JSON格式，支持自定义属性模板
  - 游戏规则：数据驱动，不由代码硬编码固定数值
  - 千人级并发：服务端需支持 ~1000 名玩家同时在线（单棋盘）
- **Business**:
  - 无付费道具，道具仅通过游戏内获取
  - 游戏为免费游玩
  - 时代切换通过专门的可视化管理应用（与地图编辑器同源）操作
- **Dependencies**:
  - 地图编辑器（已存在，提供地图数据格式定义和编辑工具）
  - 时代管理可视化应用（待开发，与地图编辑器复用组件，用于时代切换）
  - Socket.IO（实时通信）
  - i18next（国际化）

## Assumptions
- 玩家使用现代浏览器（Chrome、Firefox、Safari最新版本）
- 玩家有稳定的网络连接
- 地图由地图编辑器创建并导出为JSON格式
- 初期只支持一个游戏世界（单服务器）
- 昼夜周期暂定 15 分钟（实际值在对应配置文件中定义，便于调整）
- 每个棋盘自带属性模板定义，游戏引擎动态解析
- 单棋盘最大容量为**千人级**（~1000 名玩家同时在线）
- 时代切换对应现实世界 3-6 个月（通过类似地图编辑器的可视化应用来操作）
- 备选数值的具体名称和用途由每个棋盘自行定义（参考示例：环保值）
- 天赋系统在游戏初期提供基础选项，后续通过成就扩展
- 玩家视野始终小于棋盘（视野大小由天赋决定，支持观察周边格子）
- 存在调试开关（开发模式下可启用，禁用新手引导等流程以加速开发迭代）

## Acceptance Criteria

### AC-1: 自定义地图加载与数据驱动渲染
- **Given**: 地图编辑器导出的有效JSON地图文件（包含自定义属性模板）
- **When**: 游戏启动并加载地图
- **Then**: 棋盘正确渲染所有格子，格子位置、类型、连线与地图数据一致；自定义属性被正确解析和使用
- **Verification**: `programmatic`
- **Notes**: 验证格子数量、类型分布、连线关系、自定义字段解析是否正确；测试不同模板的地图都能正确加载

### AC-2: 掷骰移动
- **Given**: 玩家处于正常状态
- **When**: 玩家点击掷骰按钮
- **Then**: 骰子随机显示1-6的点数，玩家棋子沿路径移动对应步数，最终停在正确的格子上
- **Verification**: `programmatic`
- **Notes**: 掷骰冷却期间按钮禁用；多岔路时正确处理路径选择

### AC-3: 地产购买与升级
- **Given**: 玩家经过无主地产格且金钱充足
- **When**: 玩家选择购买地产
- **Then**: 玩家财产减少对应价格，地产所有权转移给玩家，下次经过时可升级
- **Verification**: `programmatic`
- **Notes**: 价格、升级费用、租金均从地图数据中读取，非硬编码

### AC-4: 租金收取
- **Given**: 玩家A拥有某地产，玩家B经过该地产
- **When**: 玩家B停在该地产上
- **Then**: 玩家B的财产减少相应租金，玩家A的财产增加相应租金
- **Verification**: `programmatic`

### AC-5: 监狱机制
- **Given**: 玩家踩中监狱格子
- **When**: 玩家进入监狱状态
- **Then**: 掷骰冷却大幅延长，无法收取费用，信用值降低；出狱后恢复正常
- **Verification**: `programmatic`

### AC-6: 组队与数值共享
- **Given**: 两名玩家在线，均启用了信用值系统
- **When**: 一方发送组队邀请，另一方接受
- **Then**: 两人合并为一个队伍，共享财产和信用值
- **Verification**: `programmatic`

### AC-7: 道具使用与多数值影响
- **Given**: 玩家持有查封令道具
- **When**: 玩家对某地产使用查封令
- **Then**: 该地产被查封，短时间内无法操作，使用者信用值降低
- **Verification**: `programmatic`

### AC-8: 昼夜繁荣度与时区
- **Given**: 棋盘上有时区划分
- **When**: 某时区从白天进入夜晚
- **Then**: 该时区的区域繁荣度降低，区内地产收益减少
- **Verification**: `programmatic`

### AC-9: 离线保存与多数值持久化
- **Given**: 玩家已登录且有游戏进度（包含财产、信用值、备选数值等）
- **When**: 玩家断开连接
- **Then**: 玩家的所有数值、地产、位置等状态被保存，下次登录时完全恢复
- **Verification**: `programmatic`

### AC-10: 多语言切换
- **Given**: 游戏支持中文和英文
- **When**: 玩家在设置中切换语言
- **Then**: 界面所有文本切换为目标语言
- **Verification**: `human-judgment`

### AC-11: UI视觉效果与开始动画
- **Given**: 游戏启动
- **When**: 玩家看到开始界面
- **Then**: 界面有剪影下落出现地图的动画效果，视觉风格与设计稿一致
- **Verification**: `human-judgment`
- **Notes**: 参考UI图稿中的手绘设计

### AC-12: 棋盘交互流畅度
- **Given**: 棋盘上有多个玩家和格子
- **When**: 玩家进行点击、悬停等操作，相机跟随玩家移动
- **Then**: 操作响应流畅，相机跟随平滑，无明显卡顿
- **Verification**: `human-judgment` + `programmatic`
- **Notes**: 相机自动跟随玩家，不支持手动缩放或拖动棋盘；可通过 AI 玩家采集 UI 响应时间数据辅助验证

### AC-13: 代码可维护性与数据驱动架构
- **Given**: 项目源代码
- **When**: 开发者审查代码结构
- **Then**: 代码模块化清晰，数据驱动架构，游戏逻辑与具体数值分离，有文档说明，易于理解和扩展
- **Verification**: `human-judgment`

### AC-14: 多元数值目标与天赋系统
- **Given**: 游戏支持财产、信用值、备选数值三大体系
- **When**: 玩家选择不同的天赋组合
- **Then**: 游戏体验和目标发生变化，玩家可以选择不同的发展路径
- **Verification**: `human-judgment`
- **Notes**: 验证游戏不只是单一追求财富，信用值和备选数值也是有意义的目标

### AC-15: 自定义地图扩展性
- **Given**: 地图编辑器创建的新地图（包含自定义属性）
- **When**: 将新地图导入游戏
- **Then**: 游戏能正确加载和渲染新地图，自定义属性按预期工作
- **Verification**: `programmatic`
- **Notes**: 测试添加新的自定义字段、新的行为文件等场景

### AC-16: 棋盘可见性与相机跟随
- **Given**: 玩家在棋盘上移动

- **Then**: 相机平滑跟随玩家移动，整个棋盘始终可见，无视野遮罩

- **Notes**: 无视野遮罩系统，棋盘完全可见；相机自动跟随玩家，移动平滑无跳变；原设计的视野遮罩/雾化系统未实现，保留为未来可扩展方向

### AC-17: 千人级并发性能
- **Given**: 单棋盘上有约 1000 名玩家同时在线
- **When**: 玩家进行各类操作（掷骰、移动、购买等）
- **Then**: 游戏操作响应流畅，服务端处理不卡顿
- **Verification**: `programmatic`

### AC-18: 新手引导与调试开关
- **Given**: 新玩家首次进入游戏
- **When**: 玩家开始游戏
- **Then**: 显示分步的新手引导教程，可跳过

- **Given**: 一个时代结束

- **Given**: 棋盘定义了"环保值"备选数值，可对区域设置
