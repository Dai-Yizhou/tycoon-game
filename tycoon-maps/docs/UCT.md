# UCT 理念说明书（≤2 页）

## 一句话

**UCT（Universal Cost Type，通用费用类型）** 允许不只是"钱"参与经济流动。一张地图声明它用了哪些数值字段，所有费用/收益/分红都用同一种结构描述。

## 为什么有 UCT

- 原来的效果只写死 `money`（现金）。但游戏里还有"信用值""环保值""区域繁荣"等，也应该能增减。
- 用 UCT 后，**所有字段按同一套规则参与运算**（含股份分配），不针对某个字段写死代码。
- 字段集合由地图的 `map-meta.json` 约定——**不是任何地方都能随便写一个字段**。

## UCT 的形状

```jsonc
{
  "player": { "money": -10, "credit": 0, "env": -3 },   // 玩家字段：对目标玩家生效
  "region": { "pros": -1 }                              // 区域字段：对目标区域生效
}
```

- **两类作用域**：`player`（单玩家数值）和 `region`（区域数值）。它们不能混在同一语义里，`player` 按股比拆分，`region` 按整值/规则应用。
- **字段全集来自 `map-meta.json` 的 `uct`**：

```jsonc
"uct": { "player": ["money", "credit", "env"], "region": ["pros"] }
```

- 与当前格子/操作无关的键**可以省略**，省略即视为 `0`。这不算错误，也不会触发兜底。

## 正负号规则（最重要的约定）

> **代码永远用加号运算；正负号写在数据里。**
> `目标字段 = 目标字段 + 你写的数值`  — 所以负数=扣/付，正数=加/收。

- 例：`money: -20` → 玩家现金 `+= -20`（扣 20）。
- 例：`credit: 5` → 玩家信用 `+= 5`（加 5）。
- **允许同一 UCT 内混合正负**，这是预期用法。例如一次"修缮"):
  `{ "player": { "money": -20, "credit": 5 }, "region": { "pros": 10 } }`
  表示：付 20 现金，得 5 信用，区域繁荣 +10。
- 别猜方向：**凡是"玩家支付/被扣"就写负数，凡是"玩家获得/被加"就写正数**。

## 股份分配语义

当 UCT 参与分红/扣款时，**每个 `player` 字段都按同一股比分配**，与原来钱的分红一致：

```
owner.field = owner.field + floor( delta.field × share )
```

- `floor` 保留 `delta.field` 的符号（分红为正被加，扣款为负被减）。
- `region` 字段不按玩家股比拆分。

## 谁来决定用哪些字段（自定义权限）

**这是你的自由**。每张地图用哪些数值字段，由地图制作者（协作方）在 `map-meta.json` 里自己定：

- 在 `uct` 里声明你要的字段全集（`player` / `region` 两组）。
- 在 `valueFieldDefinitions` 里给每个新字段补上名字（i18n 格式）、作用域、上下限。

```jsonc
"valueFieldDefinitions": [
  { "id": "money",      "name": { "zh-CN": "财产" }, "scope": "player", "min": 0 },
  { "id": "reputation", "name": { "zh-CN": "声望" }, "scope": "player", "min": 0, "max": 100 }
],
"uct": { "player": ["money", "reputation"], "region": ["pros"] }
```

- **声明了就能用**：新字段声明完成后，所有 UCT 语境（扣款、分红、事件）都自动支持它，不需要开发者改代码。
- **没声明就是错**：用了 `uct` 没声明的字段，会直接被判定为配置错误。
- 反过来，有些东西**不是**字段全集，不能自己加——例如 `investmentTriggers[].on` 的触发事件由服务端预定义，想要新的得向开发者申请（见 spec.md §3.5）。

## 字段速查（典型地图）

| 字段 id | 作用域 | 含义 | 典型用法 |
|---|---|---|---|
| `money` | player | 现金 | 购买、租金、费用 |
| `credit` | player | 信用值 | 修缮奖励、监禁扣减 |
| `env`    | player | 环保值 | 环境相关事件 |
| `pros`   | region | 区域繁荣度 | 修缮/事件对区域的影响 |

> 字段集合**以你所用地图的 `map-meta.json` 为准**，上表只是示例。写之前先确认该地图声明了哪些字段。

## 写错了怎么办

- 用了这张地图没声明的字段 → 会被提示"该字段不存在"，把字段加进 `map-meta` 或换用已声明的字段即可。
- 该填数字却填了别的 → 会被提示补成数字。
- 混合正负**不是错误**——一次"修缮"同时扣钱、加信用、抬繁荣正是预期用法。
