# 与 Agent 协作指南 + 最佳实践

本仓库的核心工作流由**协作者侧 Skill**驱动（入口 `AGENTS.md` → 主流程 `skills/map-author/SKILL.md`，规范详解 `SPEC.md`、充分示例 `EXAMPLES.md`）。下面是人话版说明，供人类查阅，也和 Agent 协作时共同遵守的约定。**首要纪律：先精确对齐需求与效果（谁/何时/对谁/增减多少/方向），确认"完整、无歧义"后才生成，不允许臆测。**

> 人体速记：**地图 = `map.json`（格子）+ `map-meta.json`（字段/区域/计费配置）+ `behaviors/`（行为）**。schema 单一来源在主仓库，这里只有内容。

## 一、协作的原则共识

1. **自然语言为主**：正常流程只说你要什么，不手写 JSON。
2. **先确认、后生成**：描述有歧义时，Agent 先复述 + 追问缺失项（如最高等级、升级费用），确认为"完整、无歧义"再产出。
3. **校验 = 硬门禁**：任何入库都先过校验（复用主仓库 `shared/map-parser` + UCT schema）。校验不过 = 不提交，快速失败，不静默兜底。
4. **人类可查**：不懂就问；所有规则在 `docs/` 有人类文档。

## 二、Agent 的标准对话脚本（示例）

```
协作者：我要一个 property 格子，id=5，价格 100，租金 10/20/30/40，可升 3 级。
Agent  ：收到。确认一个点：升级费用如何递增？（缺省我按 50/100/150）
协作者：50/100/150。
Agent  ：已生成，校验通过。要提交到地图仓库吗？
协作者：提交。
Agent  ：已提交。commit: abc123
```

### 什么时候 Agent 应主动追问
- 提到了"等级/递增"但没说数量或费用。
- 提到了要"分红/扣款"但没说触发条件。
- 提到了 UCT 字段但没说作用域（player/region）或正负方向。

## 三、正负号速记（最容易错的地方）

| 意图 | 写法 |
|---|---|
| 玩家支付 / 被扣 | `money: -X` |
| 玩家获得 / 被加 | `money: +X` |
| 加信用 | `credit: +X` |
| 区域繁荣升 | `region: { "pros": +X }` |

> 代码统一 `+=`；正负号写在数据里。**别写错方向**，校验能识别但不代表语义对——生成后请让 Agent 用一档句子复述效果。

## 四、schema 变更会造成存量地图失效

主仓库的 UCT/行为 schema 可能演化。规则：
- 合并进主仓库时强制重跑校验。
- 本仓库**不维护 schema 副本**；如遇校验规则变化，以主仓库为唯一事实源。

## 五、与"微信贴 JSON"回退的关系

- **首选**：Agent 对话产出 + 入库。
- **回退**：直接贴 JSON 给开发者，由开发者侧校验入库。回退时不要求完整 schema，但开发者侧会补校验并回写修正。

## 六、给人类维护者的最佳实践

- 地图按"一张图一个 `map.json` + 一个 `map-meta.json`"组织，文件可放 `maps/` 下按图分目录。
- 行为 JSON 放 `behaviors/`，命名 `*.behavior.json`。
- 任何能读到的字段（id/命名/字段全集）都要与对应 `map-meta.json` 一致，别在 `map.json` 里引入 `map-meta` 未声明的字段。

## 七、需要遵守的纪律（防技术债）

- 不新增以 `_` 开头的 hack 字段；不通过注释来"软开关"。
- 不复制主仓库 schema 到本仓库，避免漂移。
- 所有校验失败都走"报错->定位->修正"，不使用静默 fallback 掩盖配置缺陷。
