# AGENTS.md — 地图协作仓库（Agent 顶层入口）

> 任何 Agent 会话进入本仓库，**先从本文件开始**，再按指引加载制图 Skill。

## 本仓库是什么 / 不是什么

- **是什么**：游戏 `tycoon-game` 的**地图协作子仓库**。只放地图相关内容：地图 JSON、UCT 说明、协作文档、协作者侧 Skill。
- **不是什么**：不存放主仓库 schema 副本；不存放通用 agent-rules 正文；不含游戏规则/业务逻辑实现。这些以主仓库为唯一事实源。

## 协作者的 Agent 进入顺序

1. **读本文件**（AGENTS.md），了解仓库边界与入口。
2. **加载制图 Skill**：`skills/map-author/SKILL.md` —— 它是完整工作流的唯一权威驱动。按文件内索引，需要时可加载同目录 `SPEC.md`（规范详解）与 `EXAMPLES.md`（充分示例）。
3. 按 Skill 的**五步工作流**执行。**先精确对齐需求与效果，确认"完整、无歧义"后才生成/写实现，不允许臆测。**
4. 完成后同步更新该图目录的注释文档 `NOTES.md`。

## 全局硬约束（任何操作都适用）

- **先对齐、后实现，不允许臆测**：缺信息必追问；效果方向（谁、何时、增减、多少）都要先复述给人类确认。
- **改动必配注释文档**：修改 `*.map.json` / `*.map-meta.json` / `behaviors/*.behavior.json`，必须同步更新该图 `NOTES.md`。
- **一图一目录**：一张图的所有相关文件在同一目录（见 SKILL）。
- **校验 = 硬门禁**：入库前必须过校验；缺失 / 字段不在 UCT 全集 / 方向错 = 配置错误，**报错→定位→修正**，绝不静默回退。
- **不臆造字段**：只使用本仓库 schema（见 SPEC）规定的字段；需要新机制时报给开发者，不在 JSON 里发明字段或用 `_` hack。
